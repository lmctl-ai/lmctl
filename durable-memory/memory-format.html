Durable memory format: content-only HTML notes

Durable-memory notes are small HTML files that carry content only: no CSS, no class names, no emoji. A script checks them, generates the index, and builds a separate decorated copy when they are shown on a web page. Any repository can use the same format and scripts for its own durable-memory directory.

Why this format

  • Content only. Notes are read by people and by language models. Presentation (stylesheets, classes, layout) is noise for both and goes stale; the web view adds it to copies, so the sources never carry it.
  • HTML, not Markdown. HTML has one unambiguous structure that a host program can parse and check: headings, lists, tables, code and links survive any tool, and links between notes are verified.
  • No emoji. Pictographs carry no precise meaning, render differently everywhere and confuse text tools. Write the word: done, open, warning.

The profile

Files and names

  • Every note is DIR/name.html with a lowercase name of letters, digits and single hyphens. Dated notes put the date in the name: release-check-2026-10-19.html.
  • DIR/index.html must exist and link every other note. Its note list is generated (see commands).
  • One subdirectory is allowed: DIR/archive/ for retired notes. No other subdirectories.
  • Other files are reported as warnings (convert them or move them out); images referenced by notes may sit next to them.

The document

<!doctype html>
<html lang="en">
<head>
<meta charset="utf-8">
<title>Release checklist</title>
</head>
<body>
<h1>Release checklist</h1>
<p>One paragraph that says what this note is for; the index uses it as the summary.</p>
<h2 id="steps">Steps</h2>
<ol>
<li>Run <code>npm run check:memory</code>.</li>
</ol>
</body>
</html>
  • Required: <!doctype html>, <html lang>, exactly one <meta charset="utf-8">, a nonempty <title>, explicit <head>, </head>, <body>, </body> and </html> tags, and exactly one <h1>. The first paragraph after the h1 should summarize the note.
  • Head: only <meta charset>, an optional <meta name="description" content="..."> and <title>.
  • Allowed body elements: h1 h2 h3 h4 p ul ol li dl dt dd pre code kbd samp em strong a table thead tbody tr th td blockquote hr img.
  • Allowed attributes: lang on html; href on a; src, alt, width, height on img; id on h2 and h3 only (anchor targets, unique); start on ol; colspan, rowspan (and scope on th) on table cells.
  • Forbidden: class, style, any id outside h2/h3, script, link (no stylesheet), viewport meta, div, span, iframe and every other element, inline handlers (onclick and the like).
  • Images: local files only, with nonempty alt text. External resources are not allowed; links to external pages are.
  • Links between notes are relative (other-note.html, other-note.html#steps, #steps, ../index.html from archive/) and must resolve. Site-rooted links (/x) are reported: they break when the notes move. Links to repository files outside the directory resolve on disk but are not part of the web view.
  • Commands the reader types are kbd, program output is samp, both inside pre; source code is pre with code.

The emoji rule

The checker reads every note (and any other text file in the directory) code point by code point and reports the file, line and code point of these characters:

Code pointsWhat they are
U+1F000 to U+1FAFFEmoji and pictograph blocks, regional indicator flags, skin tones
U+2600 to U+27BFMiscellaneous symbols and dingbats: stars, check marks, crosses, hearts, weather
U+2B1B, U+2B1C, U+2B50, U+2B55Large squares, star, heavy circle
U+231A, U+231B, U+23E9 to U+23F3, U+23F8 to U+23FAWatch, hourglass, media and clock symbols
U+FE0F, U+20E3Emoji presentation selector, combining keycap
U+E0020 to U+E007FTag characters (subdivision flags)

Everything else is allowed, in particular punctuation (U+2000 to U+206F: dashes, quotes, ellipsis), arrows (U+2190 to U+21FF), mathematical operators, box drawing (U+2500 to U+257F) and geometric shapes (U+25A0 to U+25FF) used in diagrams.

Commands

All commands run from the repository root. They need the published lmscript compiler (npm i -g @lmctl-ai/lmctl, version 0.2.347 or newer); the runner downloads the lmhtml host pinned by SHA256 in scripts/tools/lmhtml.lock (or an lmhtml.lock next to run.sh).

CommandWhat it does
npm run check:memoryFails if the index note list is stale, then checks every note against the profile. CI runs it.
scripts/memory/run.sh index durable-memoryWrites the generated note list into index.html (title and first-paragraph summary of every note, archive/ last). Add --check to only report. Running it twice changes nothing.
npm run build:memory-webWrites the web view to build/memory-web/.
npm run check:memory:selftestProves the checker rejects each forbidden thing (fixtures in tests/memory/) and that index and web view are idempotent.

The general form is scripts/memory/run.sh check DIR, scripts/memory/run.sh index DIR [--check] and scripts/memory/run.sh web DIR OUT [--css PATH], for any directory.

Add or change a note

  1. Write durable-memory/topic-name.html from the document above: one h1, a first paragraph that summarizes it, then h2 sections.
  2. Run scripts/memory/run.sh index durable-memory to list it in the index. Edit the notes, not the generated list; text outside the list markers in index.html is yours.
  3. Run npm run check:memory until it prints check: OK, and commit the note together with index.html.
  4. Retire a note by moving it to archive/ and fixing links to it (the checker finds them).

The web view

scripts/memory/run.sh web DIR OUT writes a decorated copy of every note to OUT and never writes the sources (OUT inside DIR is refused). Each copy gains a viewport meta, one stylesheet link (default /tools/style.css, change it with --css), a nav with Index and Previous/Next links in index order, a main element around the note body, and a footer naming the source file. Images are copied as they are. Rebuilding produces identical files.

npm run build:memory-web
python3 -m http.server 8765 --directory .

Then open http://127.0.0.1:8765/build/memory-web/index.html; serving the repository root makes /tools/style.css resolve.

Use it in another repository

  1. Copy the folder scripts/memory/ of github.com/lmctl-ai/lmctl into the repository, and copy scripts/tools/lmhtml.lock into it as scripts/memory/lmhtml.lock. The raw files are also at https://raw.githubusercontent.com/lmctl-ai/lmctl/main/scripts/memory/<file>.
  2. Install the compiler once: npm i -g @lmctl-ai/lmctl.
  3. Write new notes in this format, run scripts/memory/run.sh index durable-memory and scripts/memory/run.sh check durable-memory, and add the check to CI.
  4. Existing Markdown notes can stay until someone converts them; they are reported as warnings, not errors.

Limits

  • The checker parses with lexbor through lmhtml; malformed markup is reported, not repaired.
  • Generated summaries are cut at a sentence end within 160 characters, else at a word with an ellipsis.
  • The emoji rule is a fixed list of ranges, not the full Unicode emoji property; extend is_pictographic in scripts/memory/check.lms with a fixture when something slips through.
  • The web view needs the explicit </head>, <body> and </body> tags the profile requires.
