Skill: Durable memory

Durable memory is a small, committed index of project knowledge that a new session can load quickly and expand only when needed. Start with the index, then read the chapters relevant to the task.

How it works

Keep durable-memory/index.html current with concise links and summaries. A reader opens that index first, selects the relevant chapter, and loads more chapters only when the task calls for them. Record decisions, constraints, evidence, current status and useful next steps; avoid copying a full conversation transcript.

Commit durable knowledge with the project. Keep secrets and machine-local session state out of public repositories. Ask a newly started or replacement session to read the relevant files; automatic onboarding is not guaranteed.

Recommended format for new notes

For new notes, use the content-only HTML profile: one .html file per topic, one h1, a first paragraph that summarizes the note, and h2 sections. Use semantic headings, paragraphs, lists, tables, links, and preformatted code or command/output blocks. Keep CSS, classes, scripts, presentation attributes and emoji out of the source; the web view adds presentation to a separate copy.

The profile and sample are in memory-format.html. In a project using the lmctl scripts, run npm run check:memory to validate notes and the generated index, npm run check:memory:selftest to exercise the checker, and npm run build:memory-web to build the decorated web copy. The standalone checker uses the lmhtml parser; a project can copy scripts/memory/ and its lmhtml version lock to use the same workflow.

Existing Markdown remains valid

Existing .md notes remain usable project documentation. Migration is optional: convert a note when it is useful, not just to change its extension. If a project's seed instruction still asks readers to open durable-memory/index.md, keep that single-line compatibility pointer linking to index.html until the seed accepts both formats.

Worked example

The lmctl repository's durable-memory directory is a working example of an HTML index, focused content-only chapters, validation, and a generated web view.
