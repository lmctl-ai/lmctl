lmvideo reference

Every context object, host function, host type and method of the lmvideo v0.1.124 host, generated from the published schema file schema/lmvideo.dsl.json, plus the command line, the result envelope, exit codes and the standard library the release ships.

The schema records parameter types and return types only. Parameter meanings are given where the repository documentation states them; everything else is listed as a typed signature. The same list is printed by lmvideo --lmcode-signatures.

Surface at a glance

Context objects3 (canvas, video, out)
Host function names74

Command line

The host prints this usage line for an unknown option. It is the complete list of top level modes in v0.1.124.

lmvideo --bogus
LMCODE_RETURN_BEGIN
{"ok":false,"phase":"cli","code":"CLI_USAGE","message":"usage: lmvideo --lmcode FILE [--output PATH] [--offline] | --lmcode-schema [--json] | --lmcode-signatures | --version | demo OUT.png | render IN.svg OUT.png\n"}
LMCODE_RETURN_END
InvocationWhat it does
lmvideo --versionPrints the version line, for example lmvideo 0.1.124.
lmvideo --lmcode-schemaPrints the host schema JSON. The bytes are identical to schema/lmvideo.dsl.json in the repository (SHA-256 97d1643ca2d15ed98ae76acb5a5a4828b8a3509df770b0f395569a2c96c980a2).
lmvideo --lmcode-schema --jsonSame bytes as above in v0.1.124. This is the form the lmscript compiler calls.
lmvideo --lmcode-signaturesPrints one line per context object, function and method, host and standard library together: 814 lines.
lmvideo --lmcode FILERuns compiled block bytecode and prints the result envelope between LMCODE_RETURN_BEGIN and LMCODE_RETURN_END. run_lmcode does this for you.
--output PATH, --offlineOptions of the --lmcode mode named in the usage line. The public repository does not describe them further, so they are listed here without semantics.
lmvideo demo OUT.pngWrites a built in demonstration picture (500 by 350 pixels in v0.1.124).
lmvideo render IN.svg OUT.png [--width W] [--height H] [--background COLOR]Rasterizes one SVG file to a PNG without any LMScript program.
lmvideo render-job DIR [--renderer raster|cycles] [--pass color] [--output OUT.png]Renders a scene job directory written by Scene3D.save_job.
lmvideo render-job-batch DIR [--renderer raster|cycles] [--pass color] [--output DIR]Renders a directory of frame jobs. Output is written atomically and completed frames survive cancellation.
lmvideo render-job --capabilitiesPrints accepted job options and bounds as JSON. It does not load or smoke test the renderer.
 
lmvideo render-job --capabilities
{"schema":"render-job-capabilities/v1","status":"ok","renderers":["raster","cycles"],"passes":["color"],"max_frames":32,"max_pixels":4194304,"atomic_outputs":true,"cancellation":"renderer callback; completed frames and manifest are retained"}

Envelope codes seen from the host

phasecodeCause
cliCLI_USAGEUnknown command line option.
loadLOAD_BAD_BYTECODEThe file given to --lmcode cannot be read.
loadLOAD_UNBOUNDThe program imports a function the host does not provide, for example a rest_ function.
runRUN_HOSTA host call failed, for example video.frame outside begin and end. The envelope carries line and column of the block.
appAPP_FAILThe block called out.fail. The message is the text passed to fail, prefixed with the block line and column.

Result envelope

run_lmcode returns a value with ok and, on success, result; on failure it carries phase, code, message and, when known, line and column. The result of a successful lmvideo block in v0.1.124 has these fields.

{"ok":true,"result":{"output":["drew 160x100"],"file":"build/dot.png","width":160,"height":100,"frames":1,"fps":30,"bytecode_bytes":1253,"instructions":47,"wall_ms":294,"render_calls":0,"phase_ms":{"compose":41.90718,"post":0.000943,"setup":252.409468},"max_frame_ms":0,"max_render_ms":0}}
FieldContent
outputList of the strings passed to out.print, in order.
file, width, height, frames, fpsThe output the host reports for the run, with its pixel size, frame count and frame rate.
bytecode_bytes, instructionsSize of the compiled block and the number of executed instructions.
wall_ms, phase_ms, max_frame_ms, max_render_ms, render_callsTiming and render counters. They vary from run to run.

Under --dry-run the envelope is {"ok":true,"result":null,"dry":true} and no host code runs.

Standard REST and CLI interfaces: not in v0.1.124

The current lmcode_std_v3 catalog has 226 canonical signatures. The 20 added signatures are the former lmcode_std_rest_v1 module: 5 functions and 15 RestExchange methods, together with 10 standard interfaces. lmvideo v0.1.124 was built against the 206 signature catalog, so none of the names in this section exist in that release: its signature list contains no rest_ function and no RestExchange type. A recent compiler (checked with lmscript 0.2.482) still accepts the names at compile time because it knows the newer catalog, but the v0.1.124 host refuses the program when it loads it, with code LOAD_UNBOUND, as shown below. lmvideo picks the 226 signature catalog up when a later release is built against it. The tables are provided so that a reader knows what will and will not resolve today.

prog = _lmcode_ cli="lmvideo" install="github:lmctl-ai/lmvideo@v0.1.124";
rest_stop();
end _lmcode_
r = run_lmcode(prog);
println(json_stringify(r));
{"ok":false,"phase":"load","code":"LOAD_UNBOUND","message":"import 'fn rest_stop() -> void' is not provided by the host"}
