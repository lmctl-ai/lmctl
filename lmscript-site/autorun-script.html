Writing an autorun script

Use lmctl autorun when a script needs named provider roles but should still be shareable with someone whose provider or model differs from yours. Put one machine-readable role declaration in the leading comments, then use both role markers in executable code.

This example writes a teamfile from the resolved Lead provider and model, then prints the generated path. It does not seed a provider session. Review the generated teamfile before using it with a live team workflow.

Script: autorun-script.lms

// autorun-role: Lead provider=claude model=claude-sonnet-5-5
lead_provider = "@role(Lead.provider)";
lead_model = "@role(Lead.model)";
team = path_join(Directory, "portable-team.lmctl");
contents = f"# Portable tutorial team\n_MEMBER_ alias=Lead provider={lead_provider} model={lead_model}\n";
write_file(team, contents);
println("Wrote portable-team.lmctl");

Run it

This command requires a build with lmctl autorun support; it is not included in @lmctl-ai/lmctl 0.2.373. Check lmctl --help before trying it.

lmctl autorun ./examples/autorun-script.lms

Script output when autorun executes it

Wrote portable-team.lmctl

Autorun checks whether the declared provider command is installed. If it is missing, lmctl can offer an installed provider and model mapping. In interactive mode, accept, edit, or save a proposed mapping. Non-interactive runs save proposed mappings, but the current implementation can execute when all declared providers are installed. Use --save-only before the script path to guarantee saving without execution. The saved filename receives a numeric suffix only when needed to avoid an existing file. Run that saved file with lmscript after reviewing it. Autorun also prints launcher or mapping messages; the output above is from the script itself.

The role header must use this form:

// autorun-role: Lead provider=claude model=claude-sonnet-5-5

Use one line per role. Quote a model value in the header when it contains spaces. Autorun requires both @role(Lead.provider) and @role(Lead.model) in executable source. It substitutes these values before standalone lmscript runs and updates the saved header and markers together. This preflight confirms that a provider CLI runs; it does not validate credentials. The session seed call is where authentication is tested.

If no provider is installed, autorun saves the script with the original role values and reports the missing providers. Headerless scripts keep their existing init-profile behavior and are not role-mapped. See also the marker-only example.
