Skill: Durable memory

Keep portable project decisions and operating context in committed durable-memory/ files.

What to record

Record constraints, decisions, evidence, current status, and the next useful step. Keep durable-memory/index.md current and use focused files rather than duplicating a transcript.

Onboarding

Explicitly ask a newly seeded or replacement member to read the relevant files. Automatic durable-memory onboarding is not guaranteed. A provider session and its history are distinct from committed project knowledge; do not assume session identifiers work on another machine or provider.

Version control

Commit durable knowledge. Keep secrets and machine-local session state out of public repositories; choose ignore rules for the actual project rather than assuming every teamfile must be ignored. Preserve sanitized templates where useful.

See the Lead skill for delegation and review.
