Use lmr from LMScript

lmr is a native statistics host for LMScript. It runs a fixed set of statistical operations in a C++17 runtime with no R runtime, package installation, or network access required after the binary is installed.

Purpose

Use lmr to calculate distributions, seeded random draws, hypothesis tests, regression and generalized linear models, time-series analyses, clustering, smoothing, and numerical optimization from an LMScript program.

When to use it

Use lmr when a task needs the supported statistical operations and benefits from reproducible numeric checks in a native LMScript host. Use an R environment when the task depends on arbitrary R code, packages, callbacks, or operations outside lmr's published schema.

Install

Install the LMScript compiler with npm install -g @lmctl-ai/lmctl. A released lmr binary supports Linux x64 and arm64, macOS x64 and arm64, and Windows x64. The compiler can download the matching release asset and verify its SHA-256 when the host declaration includes install.

lmscript --version
lmr --version
lmr --lmcode-schema --json

The v0.5.1 release embeds the lmr-specific schema from native/schema/lmr.dsl.json. The standard StrList methods come from the LMScript standard library and are not repeated in the host schema. Compare the released binary's JSON bytes with that file when validating a release.

Commands

Declare the released host in an LMScript program. Then compile and run the saved bytecode through that same binary.

p = _lmcode_ cli="lmr" install="github:lmctl-ai/lmr@v0.5.1";
let q = norm().q_vec(parse_vec("0.975"));
out.check_close(q.at(0), 1.959963984540054, 0.00000000000001, "normal quantile");
end _lmcode_

if (!file_exists("build")) { mkdir("build"); }
out = "build/analysis.dslb";
savedsl(p, out);
r = system ${dsl_cli(p)} --lmcode ${out};
if (r.code != 0) { println(str(r.stderr)); lm_exit(r.code); }
println(r.stdout);

Run the normal quantile example for a complete program with an expected-value check.

Inputs and outputs

The host accepts typed LMScript values, such as numeric vectors, frames, formulas, and operation options. Results use typed objects with status, estimates, diagnostics, metadata, warnings, and output vectors appropriate to each operation.

Use parse_vec to read numeric text, including NA, NaN, Inf, and -Inf. The DSL uses floating-point NaN for missing values. Values exported through out.set appear in the stdout JSON result; non-finite numbers serialize as JSON null. Random operations require a seed when deterministic output is needed.

Input limits depend on the native operation; see the API guide for operation-specific limits and result fields.

Safety rules

lmr exposes a fixed operation catalog. Optimization, integration, root finding, and nonlinear models use reverse communication: write the objective or model in the DSL and supply values through the solver object. Formula text uses the supported native formula parser; it is not evaluated as R code. The host does not run arbitrary R scripts or load user packages.

Review an LMScript file before running it. The compiler and native host execute with your local file permissions, and an LMScript program can invoke other local programs through system.

Worked examples

  • Normal quantile checks a standard-normal quantile.
  • Linear fit recovers the intercept and slope from exact points.
  • Rosenbrock minimum checks BFGS convergence against the known optimum.

The lmr repository includes longer tutorials and analysis flows.

Errors and exit codes

The host exits with code 0 when execution succeeds and all out.check assertions pass. Code 2 indicates command-line usage errors, code 3 indicates a load or execution error, and code 4 indicates an application failure such as a failed check.

When installation fails, verify the platform has a published release asset and that the tool cache can be written. When a schema mismatch appears, compare the embedded JSON and canonical signatures against the released schema using the compiler version required by the project.

How to verify

Check the version, schema bytes, and canonical signatures. Then run a fresh-cache example so lmscript downloads the released host and validates its checksum.

lmr --version
lmr --lmcode-schema --json > /tmp/lmr-schema.json
cmp /tmp/lmr-schema.json native/schema/lmr.dsl.json
lmr --lmcode-signatures > /tmp/lmr-host-signatures.txt
lmscript --lmcode-signatures native/schema/lmr.dsl.json > /tmp/lmr-compiler-signatures.txt
diff -u /tmp/lmr-compiler-signatures.txt /tmp/lmr-host-signatures.txt

For an end-to-end install check, run one of the lmr book examples with LMSCRIPT_TOOL_CACHE set to a new temporary directory and lmr absent from PATH. A host already on PATH bypasses installation.
