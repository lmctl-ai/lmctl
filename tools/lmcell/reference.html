lmcell reference

Complete reference for lmcell 0.1.4: the context object, every host type and method with its validation rules, matrix layouts, enumerated string values, limits, CLI flags, exit codes, the result envelope and the vendored lmcode_std_v3 standard library. Signatures are taken from the embedded schema and the host source.

Context objects

NameTypeRole
cellCellThe only context object: creates simulations and offers scalar helpers

The schema declares 5 host types with 36 methods, no host functions and one context object. Schema format is 2 and the schema name is lmcell.

Exit codes and result frame

ExitPhaseMeaning
0noneSuccess, also for --version, --notices and the schema flags
2cliUsage or invocation metadata error; code CLI_USAGE
3load, runBytecode could not be read or verified, or a program raised a host error
4appApplication or output failure (error code APP_FAIL)

A --lmcode invocation ends with exactly one result frame on stdout. This is the real frame for a missing file, which exits 3:

lmcell --lmcode missing.dslb
LMCODE_RETURN_BEGIN
{"ok":false,"phase":"load","code":"LOAD_BAD_BYTECODE","message":"cannot read missing.dslb"}
LMCODE_RETURN_END
Envelope fieldContent
oktrue or false
resultValue set by lmcode_return_set or the fields set by lmcode_return_put; null when unset
phaseOn failure: cli, load, run or app
codeOn failure: for example CLI_USAGE, LOAD_BAD_BYTECODE, RUN_HOST
message, line, columnOn failure: host message with the block line and column

Standard library (lmcode_std_v3)

lmcell 0.1.4 vendors the lmcode_std_v3 catalog with 206 canonical signatures: 83 function signatures and 123 method signatures on 16 standard types. The SDK is pinned in sdk.lock to lmcode-cpp commit 93bddf1dadff84791ea90e17d81a7af85a842f40. The library is registered by default, needs no import and is callable in any lmcell block next to the cell context. The result sink functions are what fill the result field of the run_lmcode envelope.

Standard REST and CLI interfaces (current catalog, not yet in this host)

The current lmcode_std_v3 catalog in lmcode-cpp has 226 canonical signatures. The 20 signatures beyond the 206 that lmcell vendors are the former lmcode_std_rest_v1 module: 5 functions and 15 RestExchange methods, together with 10 standard interfaces. lmcell does not ship them yet; it picks them up when it syncs its pinned lmcode-cpp SDK and publishes a release. Until then a lmcell program that calls rest_route or declares a RestGet handler does not compile against the lmcell schema.
