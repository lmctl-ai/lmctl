Agentic recipes

These recipes build agent workflows from short lmscript files: agents with roles and goals, tasks run in order or by a manager, routing, tools, human approval, parallel reviewers, saved state and local knowledge. Each one is a single script you can read top to bottom. The script owns every step, every model call and every tool call; nothing runs in hidden framework state.

Model calls use llm_prompt, which sends one prompt to Ollama Cloud, OpenRouter or DeepSeek and returns a map with ok, text and error. Set LLM_MODEL to a provider/model selector and export the matching key: OLLAMA_API_KEY, OPENROUTER_API_KEY or DEEPSEEK_API_KEY. Without LLM_MODEL the recipes use deepseek/deepseek-chat. Keys are read from the environment and never printed.

These recipes need an lmscript release that includes llm_prompt with the json and retries options and json_validate.

Recipes

  1. Triage router — Classify a support ticket with a validated JSON reply, then hand it to the matching specialist.
  2. Sequential crew — Run a researcher, a writer and an editor in order, each task seeing the previous output.
  3. Hierarchical manager — A manager agent assigns work to named workers until it declares the goal done.
  4. Tool agent — The model asks for built-in read-only tool calls in JSON; the script runs them and feeds the results back.
  5. Human checkpoint — A draft waits for an operator: y approves, n rejects, any other text is feedback for a revision.
  6. Fan-out and judge — Reviewers answer in parallel, then a judge returns one validated verdict with a reason.
  7. Stateful checkpoint — Save each step result to state.json so a rerun skips finished steps and resumes.
  8. Keyword knowledge — Score paragraphs of local files against a question and answer only from the best matches.

Offline and live runs

Every recipe page shows two outputs. The offline output comes from examples/mock-model.lms, an lmmock script that answers like a chat model with fixed replies chosen by the agent role, so the site check can run every recipe without a key or network access. The live output is a recorded run against a real model; it is not rerun by the check.

Script: agentic.lms

# Shared helpers for the agentic recipes: an agent is a map, ask() is one llm_prompt turn.
# Model: LLM_MODEL, default deepseek/deepseek-chat. Keys come from the environment and are never printed.
MODEL = env("LLM_MODEL", "deepseek/deepseek-chat");

fn agent(role, goal) {
  return {role: role, goal: goal, model: MODEL};
}

fn system_for(a) {
  return f"You are the {a.role}. Your goal: {a.goal}. Reply with the requested output only.";
}

fn ask(a, prompt) {
  r = llm_prompt(a.model, prompt, {system: system_for(a), temperature: 0, max_tokens: 700, retries: 2});
  if (r.dry_run) { return f"(dry run: {a.role})"; }
  if (!r.ok) {
    error(f"{a.role} failed: {r.error.code}");
    exit(1);
  }
  trace(a.role, r);
  return trim(r.text);
}

# One JSON object that must match schema; the validator's errors are fed back for up to 2 retries.
fn ask_json(a, prompt, schema) {
  request = prompt + "\nReply with one JSON object matching this JSON Schema: " + json_stringify(schema);
  for (attempt in range(0, 3)) {
    r = llm_prompt(a.model, request, {system: system_for(a), temperature: 0, max_tokens: 700, json: true, retries: 2});
    if (r.dry_run) { return null; }
    if (!r.ok) {
      error(f"{a.role} failed: {r.error.code}");
      exit(1);
    }
    trace(a.role, r);
    value = json_parse_safe(r.text, null);
    checked = json_validate(value, schema);
    if (checked.ok) { return value; }
    request = prompt + "\nYour last reply was rejected: " + join(checked.errors, "; ") + "\nReply with one JSON object matching: " + json_stringify(schema);
  }
  error(f"{a.role} gave no valid JSON after 3 attempts");
  exit(1);
}

# Append one event per model call to trace.jsonl (role, tokens, latency; never prompt text or keys).
fn trace(role, r) {
  append_file("trace.jsonl", json_stringify({role: role, model: r.model, tokens: r.usage.total_tokens, latency_ms: r.latency_ms, attempts: r.attempts}) + "\n");
}

agent returns a map. ask sends one prompt with the agent role and goal as the system prompt, retries rate limits and server errors twice, and stops the script with the error code if the call fails. ask_json asks for a JSON object, checks it with json_validate and sends the validation errors back for up to two more attempts. trace appends the role, token count and latency of each call to trace.jsonl, never the prompt text.

Try it: download examples/agentic.lms with any recipe into an examples/ directory, export your provider key, and run the recipe with lmscript.
