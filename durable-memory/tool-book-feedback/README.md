# Tool book feedback instructions

Each tool team dogfooding the publishing skill adds findings to NAME.md in this directory. Record the step, file or command, what was unclear or wrong, and a proposed correction. Include failed assumptions, prerequisites that were missing, successful checks, and any accessibility, link or image-layout issues found in browser review.

The GitHub README is part of the dogfood. Record whether the tool-specific hero idea was clear and representative, whether docs/readme lmscript sources and the render script were sufficient, whether the gallery linked to both source and published examples, whether the pipeline diagram matched the actual API, and whether light/dark desktop/mobile review exposed problems. The Lead reconciles findings into the publishing skill and asks the next team to repeat the loop.
