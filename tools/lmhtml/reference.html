lmhtml reference

Command-line flags, native commands, exit codes, host types, methods and standard-library signatures of lmhtml 0.7.6. Signatures are copied from lmhtml --lmcode-signatures, which prints 305 lines: 2 context objects, 71 host methods on 7 host types, 6 host functions, and the 226 canonical signatures of the lmcode_std_v3 standard catalog.

Host protocol flags

CommandEffect
lmhtml --versionPrints lmhtml and the version number.
lmhtml --lmcode-schemaPrints the schema summary: contexts, functions and each type with its methods.
lmhtml --lmcode-schema --jsonPrints the embedded schema JSON (dsl.schema 2, name lmhtml) used by the lmscript compiler.
lmhtml --lmcode-signaturesPrints every registered canonical signature, host and standard, one per line.
lmhtml [--dry-run] --lmcode FILE [FILE ...]Runs compiled program files written by run_lmcode. With --dry-run, saves are reported but not written.

With no arguments or a bad flag the host prints its usage text and a JSON envelope with code CLI_USAGE between the lines LMCODE_RETURN_BEGIN and LMCODE_RETURN_END.

Native commands

CommandFlagsEffect
lmhtml md2html IN.md [OUT.html]--template FILE, --allow-htmlConvert Markdown to HTML. Prints HTML when no output file is given. Raw HTML is disabled unless --allow-html is given.
lmhtml index DIR--order FILE, --checkWrite DIR/index.md. With --check nothing is written and index drift fails.
lmhtml mdcheck DIRCheck the Markdown notes in a directory; broken links fail.
lmhtml site DIR OUT--template FILEBuild a static note site from a notes directory.
lmhtml lint PATHS--stats, --json, --config FILE, --compare BEFORECount plain-content violations per file and in total. The config file holds DIRECTORY METRIC MAX_COUNT rows.
lmhtml md-lint PATHSMarkdown variant of lint listed in the usage text.
lmhtml normalize PATHS--checkRemove inline typography, repair entities and unfold prose without changing the text.
lmhtml clean URL-or-file--base URL, --markdown, --checkExtract main content. Files are processed offline; URL input uses curl. --check fails with a diff if content would be dropped.

Exit codes

CodeMeaning
0Success.
2Usage error: the usage text is printed.
3Program load failure, host runtime error, or a native command error such as an unknown option or index drift.
4Application failure, such as a report marked failed with fail_if_any, or an output stream error.

Used from lmscript

FormMeaning
p = _lmcode_ cli="lmhtml" install="github:lmctl-ai/lmhtml@latest"; ... end _lmcode_Declares a block compiled against the lmhtml schema; install lets lmscript download the release binary.
r = run_lmcode(p)Runs the block on the host and returns a map with ok and result.
$return.name = valueSets a named field of the result, as in the repository README example.
lmscript --check FILE.lmsCompiles every block against the host schema without running it.

Standard REST and CLI interfaces

A function inside a block implements one of ten standard interfaces and carries a route, command or option annotation written as @"..." on the line before it. Each handler takes one RestExchange. The README example dispatches them statelessly with rest_cli.

InterfaceAnnotationRole
RestGetroute path such as /healthHandles HTTP GET requests for the route.
RestPostroute path such as /healthHandles HTTP POST requests for the route.
RestPutroute path such as /healthHandles HTTP PUT requests for the route.
RestDeleteroute path such as /healthHandles HTTP DELETE requests for the route.
RestPatchroute path such as /healthHandles HTTP PATCH requests for the route.
RestHeadroute path such as /healthHandles HTTP HEAD requests for the route.
RestOptionsroute path such as /healthHandles HTTP OPTIONS requests for the route.
RestHandlerroute pathGeneral route handler interface.
CliCommandcommand name such as textA stateless CLI command.
CliOptionoption name such as --selectorA CLI option handler, run before the command.
