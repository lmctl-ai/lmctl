lmcode-c-sample guide

This guide walks through the architecture of lmcode-c-sample, covering C11 + C++17 arena ownership, schema embedding, R49 rule dispatch, dry mode, and corpus verification.

Overview

src/domain.h and src/domain.c implement Money, Items, Shop, and Ledger in portable C11 with an arena owning stable Money pointers and zero C++ or VM dependencies (verified standalone by make test-domain). src/bindings.cpp wraps those C functions in dslvm::Registry callbacks, translating nonzero C status codes into dslvm::Error without letting C++ exceptions cross the extern "C" boundary. src/main.cpp implements the CLI discovery flags, LMCODE_INVOCATION_FILE dry-mode gate, R49 @item and @total rule entry dispatch, and LMCODE_RETURN framing.

Domain schema and registry bindings

The host registers two contexts (shop: Shop and ledger: Ledger), four object types (Money, Items, Shop, Ledger), the Currency enum, overloaded factory functions money(int) and money(float), arithmetic operator methods (plus, minus, times, neg), collection iteration methods (Items.len and Items.at), and two R49 SAM interfaces (Adjuster and Score). All 45 host signatures coexist with the default lmcode_std_v3 catalog.

Rule entry dispatch and standard interfaces

After the program body finishes, the host iterates Program.entries() in source order: every entry annotated @item implementing Score(Money) -> int is invoked once per shop item handle, and every entry annotated @total implementing Score(Money) -> int is invoked once with shop.total(). Non-void entry returns print 'entry NAME = VALUE' and increment entries_called.

./build/lmcode-c-sample --version
./build/lmcode-c-sample --lmcode-schema --json
./build/lmcode-c-sample --lmcode-signatures
./build/lmcode-c-sample --lmcode sample-suite/bytecode/001-literals.dslb

Invocation result protocol and dry mode

The sample CLI reads LMCODE_INVOCATION_FILE when present, propagates dry mode to Context before domain setup, allocates an independent ResultSink for each --lmcode, --first, or --last slot, and emits one terminal LMCODE_RETURN_BEGIN / LMCODE_RETURN_END frame after all bodies, @item and @total rule entries, and the non-negative ledger balance application check finish.

Conformance verification

Running ./test.sh verifies sdk.lock and suite.lock, compiles the host, audits that every standard and host signature is covered by the corpus, checks --version, --lmcode-schema [--json], and --lmcode-signatures, runs all 123 canonical bytecode cases byte-for-byte against expected stdout and exit codes (0, 2, 3, 4), verifies dry-mode sentinel isolation, and runs negative harness mutation controls.
