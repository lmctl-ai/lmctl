lmcode-csharp skill

Use lmcode-csharp to embed the DSLB v6 bytecode runtime, 226-signature standard catalog, and REST/CLI controller into .NET 8 and NativeAOT C# hosts.

Purpose

Build reflection-free, NativeAOT-ready C# host applications that verify and execute lmcode DSLB v6 programs and emit LMCODE_RETURN envelopes.

When to use it

Use lmcode-csharp when authoring a .NET 8 application or NativeAOT binary that exposes C# domain objects or REST/CLI routes to compiled lmcode bytecode.

Install

Reference src/LmCode/LmCode.csproj with dotnet add reference or vendor the src/LmCode directory in a .NET 8 SDK project.

Commands

dotnet build -c Release -warnaserror
dotnet test
dotnet run --project conformance/LmCode.Conformance -- conformance/vectors
dotnet run --project conformance/LmCode.Conformance -- conformance/stdlib-vectors
dotnet publish examples/Greeter -r linux-x64 -c Release -p:PublishAot=true

Inputs and outputs

  • Input: byte[] DSLB v6 bytecode, byte[] dsl.schema: 2 JSON, and optional LMCODE_INVOCATION_FILE manifest.
  • Output: mutated C# objects in Context, HTTP/1.1 responses over stdio via RestController, or a terminal LMCODE_RETURN frame.
  • Strings: VmString stores immutable raw bytes accessed via .Span; decode UTF-8 with .ToString() only when text is required.

Safety rules

  • Never round-trip arbitrary VmString byte payloads through C# UTF-16 string unless UTF-8 validity is guaranteed.
  • Keep object handles (ObjRef) scoped to their owning Context and do not share mutable handles across concurrent runs.
  • Use Registry.Dry(callback) to provide safe dry-mode previews while leaving mutating callbacks unslotted.

Worked examples

var registry = new Registry();
registry.Function("greet", ["string"], "void", (_, values) =>
{
    Console.Error.WriteLine("Hello, " + values[0].AsStr().ToString());
    return Value.None;
});
var program = LmCode.Program.Load(File.ReadAllBytes(path), schemaBytes, registry);
var context = new Context();
program.Run(context, registry);
