lm3d Java 3D application skill

Use lm3d to build a browser scene graph and WebGL renderer in Java, compiled by TeaVM without a JavaScript 3D runtime.

Purpose

Create Java scenes with meshes, indexed geometry, basic or Phong materials, lights, perspective or orthographic cameras, and orbit controls. Render them into an HTML canvas through WebGL 1. Start with the quick reference, the working demo, and the public source.

When to use it

Use lm3d when Java should own scene objects, transforms, rendering, and browser events, or when a TeaVM application needs a small familiar 3D API. It is suitable for focused visualizations and teaching examples. It is not a drop-in Three.js replacement and currently has no textures, model loaders, shadows, post-processing, or transparent-object sorting.

Install

Install Java 21 and Maven, then clone and build the public repository. lm3d is not published to Maven Central; mvn install places com.lmctl:lm3d:0.1.0 in the local Maven repository. Node 24.15 or newer and Playwright are test-only dependencies.

git clone https://github.com/lmctl-ai/lm3d.git
cd lm3d
mvn clean install

Commands

Build the library and static demo, or override demo.output to generate the deployable assets elsewhere:

mvn clean package
mvn -Ddemo.output=/absolute/site/path clean package

Run the JVM and real-browser suites:

mvn clean verify
npm ci
npx playwright install --with-deps chromium
npm test

Inputs and outputs

  • Inputs: Java scene code, TeaVM JSO canvas references, geometry arrays or built-in geometry parameters, colors, light intensities, and browser events.
  • Build outputs: the lm3d JAR and target/demo/ containing demo.html, demo.css, teavm.js, boot.js, and favicon.svg.
  • Runtime outputs: WebGL frames, draw-call and triangle counts, scene transforms, and application-defined DOM status.
  • Geometry input: float XYZ positions, matching float XYZ normals, and char triangle indices. Arrays are defensively copied.
  • Renderer output: the one-argument constructor uses a non-preserved buffer; the two-argument constructor can preserve it for screenshots and readback.

Safety rules

  • Treat Java and TeaVM build inputs as trusted code. Do not compile or execute unreviewed generated JavaScript.
  • Validate external numeric geometry data before allocating arrays. Limit vertices and indices, reject malformed lengths, and keep each index within the vertex array.
  • Use innerText for untrusted labels or errors. lm3d does not sanitize application HTML.
  • Call renderer.dispose when permanently replacing a renderer to release GPU buffers and its program. Replacing many immutable geometries in one renderer retains their cache entries until disposal.
  • Preserve drawing buffers only when readback is required; normal rendering should use the default non-preserved buffer.
  • Handle unavailable WebGL and shader errors visibly. Test on the target browser and GPU, including software WebGL in CI.

Worked examples

  1. Create a Scene and PerspectiveCamera, position the camera, and call lookAt.
  2. Create a Mesh with BoxGeometry and MeshPhongMaterial, set its position, and add it to the scene.
  3. Add AmbientLight and DirectionalLight. A directional light points from its position toward its target, whose default position is the origin.
  4. Construct WebGLRenderer with the canvas, call setSize, and render the scene and camera.
  5. For hierarchy, call scene.add(group) and group.add(mesh) as separate statements. Object3D.add returns its receiver.
  6. For animation, update Java transforms inside Window.requestAnimationFrame and render again. For camera input, create OrbitControls with the same camera and canvas.
  7. For screenshot or pixel tests, construct WebGLRenderer(canvas, true). Read renderer.triangles() and renderer.drawCalls() after rendering.

The complete compilable scene and imports are in the quick reference and repository README.

Errors and exit codes

Maven returns nonzero for Java compilation, TeaVM compilation, or JVM test failures. npm test returns nonzero for browser launch, assertion, HTTP, console, page, or WebGL errors. Constructors throw IllegalArgumentException for invalid dimensions, arrays, indices, projections, or null required objects. Matrix4f.invert throws IllegalStateException for a singular matrix. WebGLRenderer throws IllegalStateException when WebGL is unavailable or shader compilation/linking fails; include its message in an accessible status.

How to verify

  1. Run mvn clean verify to execute the JVM tests and generate the TeaVM site.
  2. Run npm test with Chromium installed. The test starts its own local server.
  3. Exercise actual geometry selection and pointer/wheel events, not just Java compilation.
  4. Read WebGL pixels and check gl.getError. A DOM canvas element alone does not prove a scene rendered.
  5. Check animation frames differ, pause makes them stable, resume restarts motion, and controls still redraw while object motion is paused.
  6. Check desktop and narrow mobile layouts, external requests, console errors, and page errors. Set DEMO_URL to repeat the suite against production.
