integration

integration provides hermetic E2E scenarios, the ported mono-test suite, and reusable GitHub Actions for published lmctl, lmscript, and lmcode releases.

Quick reference

Run hermetic T0 and T1 scenarios against installed releases, run the ported 88-entry mono-test suite and its negative controls, or invoke the reusable setup action in GitHub Actions.

bash tests/setup-selftest.sh
bash scripts/run-scenario.sh scenarios/t0-claudemock
bash scripts/run-scenario.sh scenarios/t0-fanout
bash scripts/run-scenario.sh scenarios/t1-lmmock-ai
bash tests/scenario-controls.sh
node suites/mono-test/run.mjs
node suites/mono-test/run.mjs --control broken-bin
bash tests/suite-controls.sh
Component Path Purpose
Reusable setup action actions/setup (lmctl-ai/integration/actions/setup@<sha>) Install @lmctl-ai/lmctl in RUNNER_TEMP and SHA-256-verify released lmcode hosts and extra assets.
T0 ClaudeMock scenarios scenarios/t0-claudemock, t0-fanout, t0-provider-smoke-mock Verify lm_prompt, lm_fanout slot ordering, multi-turn seeds, and error handling offline.
T1 lmmock scenarios scenarios/t1-lmmock-ai, t1-lmmock-modes Verify lmscript -> lmctl -> miniplayer acp -> HTTP -> lmmock across ok, retry (429), 401, 500, and bad-json modes.
Ported mono-test suite suites/mono-test/run.mjs (inventory.tsv, allowlist.json) Run the hermetic subset of the 88 lmctl-mono-test suites against the published lmctl package.
Negative control suites tests/setup-selftest.sh, scenario-controls.sh, suite-controls.sh Prove that corrupted checksums, bad tags, wrong replies, and vacuous binaries fail the gate.

Runnable scenario and control verification example executing T0 scenarios in a hermetic temporary HOME:

bash tests/setup-selftest.sh
bash scripts/run-scenario.sh scenarios/t0-claudemock
bash scripts/run-scenario.sh scenarios/t0-fanout
bash scripts/run-scenario.sh scenarios/t0-provider-smoke-mock
