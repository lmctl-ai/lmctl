lmr reference

Every command-line flag, exit code, context object, host type, method and function of the lmr host, generated from the schema embedded in the repository (native/schema/lmr.dsl.json, dsl.schema 2, name lmr) and from native/src/host/main.cpp. The host schema declares 166 functions with 234 signatures and 50 types with 604 method signatures; the vendored standard library adds 206 more signatures.

Command line

CommandEffect
lmr --versionPrints lmr followed by the release version and exits 0.
lmr --lmcode-schemaPrints a readable summary of the registry: context and function signatures, then each type with its methods.
lmr --lmcode-schema --jsonWrites the embedded schema JSON byte for byte; this is what lmscript compiles against.
lmr --schemaAccepted as an alias of --lmcode-schema, with the same optional --json.
lmr --lmcode-signaturesPrints one canonical signature per line from the live registry.
lmr --generate-schemaPrints schema JSON generated from the live registry (used to maintain the schema file).
lmr --lmcode FILE [FILE ...]Loads and verifies every compiled program file, then runs them in order and writes one result frame to stdout.
lmr --lmcode FILE --lmcode FILEThe repeated-flag form is also accepted for multi-file runs.

Any other argument shape prints the usage line to stderr and is reported as a usage error. All program files are loaded and verified before any of them runs, so a broken later file leaves no output from an earlier one.

Exit codes

CodeMeaning
0Success: the program ran and every out.check assertion passed.
2Command-line usage error (error code CLI_USAGE).
3Load or run error, for example bytecode that fails verification (LOAD_BAD_BYTECODE) or a registry error.
4Application failure: one or more out.check calls failed (APP_FAIL).

Run result

From LMScript, run_lmcode(prog) returns an object with ok and result. For lmr the result holds values (everything stored with out.set, in first-set order), checks (the number of out.check calls) and failures (the number that failed). Non-finite numbers serialize as JSON null.

Standard REST and CLI interfaces

These do not apply to lmr today. The std schema vendored in this repository contains no rest_ functions and none of the RestGet, RestPost, RestPut, RestDelete, RestPatch, RestHead, RestOptions, RestHandler, CliCommand or CliOption interfaces. They belong to the 226-signature lmcode_std_v3 catalog (rest_config, rest_route, rest_serve, rest_stop, rest_cli and the RestExchange methods) and become available to lmr blocks only after lmr updates its SDK pin and ships a release with it. Confirm with lmr --lmcode-signatures on the binary you run.
