lmscript

lmscript is a small scripting language and command-line interpreter for automating files, data, processes, native tools, and AI teams. A script is checked before it runs; a dry preflight previews effects before the real pass.

Start with the tutorials in order. Each chapter includes a script you can download, a command to run it, and output from the published compiler.

New to lmscript? Follow the numbered path first, then keep the quick cheat sheet nearby. The command names, braces, semicolons, and function calls should feel familiar if you know another programming language; the built-ins and host blocks are specific to lmscript.

Reading order

  1. Hello and variables — Start with a variable, an argument, and an f-string.
  2. Quick cheat sheet — One-page syntax and the built-ins used most often.
  3. Control flow and functions — Use a function and a loop to compute a result; continue skips one iteration.
  4. Strings and data — Read JSON data, update a list, build a map, and format the result.
  5. Files and processes — Write and read a temporary file, then run a process as an argument array without a shell.
  6. Errors and require — Use require for a condition that must hold; a failed requirement stops the run with an error.
  7. Typed host blocks — Compile native host calls with install declarations for lmdraw, lmcad, and lmhtml.
  8. Driving teams — The default path is offline. Enable live mode to seed a configured Lead, prompt once, then open its terminal in interactive mode.
  9. Writing a team automation — Build a repeatable workflow from team setup, seeding, prompts, checks, and a final handoff.
  10. A small multi-agent workflow — Lead assigns work to Coder; Reviewer checks it; Lead handles revisions.
  11. Writing an autorun script — Declare provider roles and placeholders so lmctl autorun can map them on another machine.
