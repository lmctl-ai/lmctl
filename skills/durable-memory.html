Skill: Durable memory

Durable memory is a small, committed index of project knowledge that a new session can load quickly and expand only when needed. Start with the index, then read the chapters relevant to the task.

How it works

Keep durable-memory/index.md current with concise links and summaries. A reader opens that index first, selects the relevant chapter, and loads more chapters only when the task calls for them. Record decisions, constraints, evidence, current status and useful next steps; avoid copying a full conversation transcript.

Commit durable knowledge with the project. Keep secrets and machine-local session state out of public repositories. Ask a newly started or replacement session to read the relevant files; automatic onboarding is not guaranteed.

Recommended format for new notes

Write durable-memory chapters in Markdown: one h1 title, a concise opening paragraph, h2/h3 sections, lists, tables, fenced code and relative links. Keep content focused and omit emoji. An optional front-matter block can provide title and summary metadata.

index.md is generated from chapter titles and summaries. Read it first, then load only relevant chapters. Run npm run build:memory-index after editing a note, and commit the note with its generated index. The index is ordinary Markdown, not a compatibility pointer.

Run npm run check:memory to check index drift, internal links and anchors, and the no-emoji policy. npm run check:memory:selftest tests these rules. The wrappers use the checksum-pinned lmhtml release; native Markdown commands need no lmscript compiler.

Use npm run build:memory-web for an optional HTML view under build/memory-web. The shared template is outside the notes; source Markdown stays unchanged and is not published by the site's static deploy workflow.

The Markdown format guide documents authoring, the generated index, template placeholders and standalone lmhtml index, lmhtml mdcheck, and lmhtml site commands. This skill page and other skills remain HTML-only.
