Use lmtorch from LMScript

lmtorch is a CPU tensor and neural network host for LMScript. It runs compiled DSL blocks with native tensor operations, automatic differentiation, model layers, optimizers, and local tensor files.

Purpose

Use lmtorch when a local LMScript program needs tensor math, gradients, model training, or safetensors and CSV input or output. A DSL block runs in one process, so intermediate tensors stay in memory.

When to use it

Use lmtorch for deterministic CPU tensor workflows and small models. Choose another host when the task requires a GPU, remote training service, or Python package ecosystem.

Install

Install Node.js 24.15 or newer and LMScript with npm install -g @lmctl-ai/lmctl. A host declaration with cli="lmtorch" install="github:lmctl-ai/lmtorch@v0.5.1" downloads the matching release binary when lmtorch is not on PATH and verifies its SHA256SUMS checksum.

The lmtorch v0.5.1 release embeds its host-specific DSL schema. Standard functions come from the LMScript standard library and are not repeated in the host schema. LMScript uses the schema reported by the same binary that executes the compiled bytecode. This release supports Linux x64 and arm64, macOS x64 and arm64, and Windows x64.

Commands

Save a DSL block to bytecode and run it through the host command prefix.

p = _lmcode_ cli="lmtorch" install="github:lmctl-ai/lmtorch@v0.5.1";
let x = torch.tensor("[1.0, 2.0, 3.0]");
out.set("sum", x.sum().item());
end _lmcode_
savedsl(p, "program.dslb");
run = system ${dsl_cli(p)} --lmcode program.dslb;

Check run.code before using run.stdout. The host prints a JSON result for values set through out.

Inputs and outputs

Create tensors from JSON arrays or Torch constructors. Tensor operations return tensors; methods such as item, item_int, shape, and to_text return scalar or textual values. Set output fields with out.set and check expectations with out.check.

Tensor.save and Torch.load use safetensors. Torch.read_csv loads numeric data, and Tensor.write_csv writes numeric results. Keep artifact paths inside the current working directory.

Safety rules

The host and LMScript run with the local user's permissions. Review scripts before running them. The install declaration downloads a native executable from the public lmtorch release. Keep generated artifacts in a dedicated working directory.

Worked examples

The tensor sum example reduces a two-by-two tensor and checks the result. The autograd example differentiates a sum of squares and verifies that the gradient is 2x.

For a training workflow, see classify-moons-dsl.lms in the public repository.

Errors and exit codes

A compiler schema error usually means LMScript is too old or its host declaration is invalid. Upgrade @lmctl-ai/lmctl and check the cli and install values. A nonzero host exit means compilation or execution failed; read stderr before using the output.

Invalid tensor shapes and unsupported dtypes are rejected by the host. Check the shape and dtype at the operation that failed. File operations also fail when a path is missing, outside the working directory, or already exists when an exclusive output is required.

How to verify

Run the tensor sum quickrun and confirm its result is 10. For gradients, run the autograd quickrun and confirm the derivative is [2, -4, 6]. The repository test.sh runs the host API checks and examples.
