Author an lmdart application

Use this skill to build a browser application with Dart-generated JavaScript, static HTML templates, JSON data, and registered JavaScript handlers. Keep the runtime small and use browser APIs directly.

Purpose

lmdart demonstrates hydration, HTML table binding, SVG, Canvas 2D, charts, plots, animation, numeric attribute and position tweening, and WebGL. It is a focused example library rather than a component framework.

The public demo root is the book cover. Each chapter is an independent demo-topic.html page. The HTML contains no inline scripts or inline event handlers. Runtime data is loaded from local JSON files.

When to use it

  • Use lmdart when application rendering and event logic should be written in Dart and compiled to JavaScript.
  • Use hydration when static server-rendered or authored HTML should gain values and behavior without replacing its structure.
  • Use JsonTable for rectangular JSON models that should become accessible HTML tables.
  • Use SVG for retained inspectable elements and Canvas for immediate or frequently redrawn output.
  • Use the chart functions for compact fixed-layout charts and TweenPlayer for numeric SVG animation.
  • Use WebglCube as a minimal direct WebGL example, not as a full 3D engine.

Install

Use Linux x64 or arm64 with curl, unzip, Python 3, and Node 24.15 or newer for browser tests. The pinned installer selects and checksum-verifies official Dart SDK 3.14.1.

git clone https://github.com/lmctl-ai/lmdart.git
cd lmdart
scripts/install-dart.sh
bash scripts/build.sh

The SDK stays in the ignored .tools directory. package:web 1.1.1 supplies typed browser bindings. No Flutter SDK or npm runtime package is required.

Commands

Generate and compile the complete static site with one command.

bash scripts/build.sh

Choose another output directory with an absolute path.

bash scripts/build.sh /absolute/site/path

Run static analysis, VM tests, and browser integration separately.

.tools/dart-sdk/bin/dart analyze
.tools/dart-sdk/bin/dart test -r expanded
npm ci
npx playwright install --with-deps chromium
npm test

After changing chapter templates in scripts/generate-book.py, regenerate and review the source diff.

python3 scripts/generate-book.py
git diff --check

Inputs and outputs

JSON validators require objects with string keys, arrays, strings, and finite numbers as appropriate. JsonTable requires nonempty columns and rows of matching length. Pie slices must be nonnegative with a positive total. Tween duration must be positive. WebGL data supplies six hexadecimal colors and a finite speed.

The compiled lmdart.js installs window.LMDart. boot.js registers handlers and then calls LMDart.start. Do not call start before registration is complete.

Safety rules

  • Do not add Flutter, React, D3, Three.js, or another UI, chart, animation, or 3D framework.
  • Do not construct HTML with innerHTML. Hydrate existing nodes or create elements and use textContent.
  • Load JSON through HTTP rather than opening file URLs. Validate values before using them as coordinates or timing parameters.
  • Keep handler names unique and nonempty. Unknown handlers throw instead of silently doing nothing.
  • Pass one ordinary context object across the JavaScript boundary. Convert return values with dart:js_interop rules.
  • Convert pointer coordinates from CSS display size to logical canvas coordinates.
  • Cap animation frame deltas and provide pause and reset behavior.
  • Treat WebglCube as an example with a preserved buffer for tests, not as a complete retained 3D renderer.

Worked examples

Register JavaScript, call Dart, and update an existing element.

LMDart.register('card.clicked', context => {
  const message = LMDart.call('dart.stamp', { value: context.value });
  LMDart.setText('#result', message);
});
LMDart.start();

Hydrate static HTML after loading its JSON values.

final data = jsonMap(await fetchJson('data/card.json'), 'card');
hydrate(document.getElementById('card')!, data);

Render the same command-oriented data concept to either 2D backend.

drawSvg(svgContainer, await fetchJson('data/scene.json'));
drawCanvas(canvasElement, await fetchJson('data/scene.json'));

Create an attribute and position tween and draw additional Canvas output from the same frame callback.

final player = TweenPlayer(await fetchJson('data/tween.json'),
  onFrame: (seconds) => drawParticles(canvas, seconds));
player.start();

Errors and exit codes

JSON shape and value failures use FormatException. Missing DOM elements and unavailable Canvas or WebGL contexts use StateError. Duplicate, empty, and unknown runtime handlers use ArgumentError. The page dispatcher reports startup failure in its status element and rethrows for browser diagnostics.

The SDK installer exits nonzero for unsupported platforms, download failure, or checksum mismatch. Dart analysis, tests, and compilation return nonzero on errors. Browser tests return nonzero for HTTP errors, runtime errors, wrong output, interaction failures, third-party requests, or mobile overflow.

How to verify

  1. Run dart analyze and require no issues.
  2. Run the 12 VM tests for models, scales, tween math, and matrices.
  3. Build the site and confirm generated HTML is synchronized.
  4. Run npm test and require all nine pages to pass without browser or HTTP errors.
  5. Click hydration and table controls, redraw SVG, add Canvas marks, and invoke JavaScript-to-Dart calls.
  6. Verify chart pixels, SVG arc paths, position and attribute changes, animation pause/reset, and WebGL pixels with gl.getError equal to zero.
  7. Check the book at narrow mobile width and confirm no third-party runtime requests.
  8. For deployment, set DEMO_URL to the public root URL and rerun the browser suite.
