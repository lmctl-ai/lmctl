lmcode-python skill

Use lmcode-python to embed the DSLB v6 bytecode verifier, 206-signature standard catalog, and opt-in REST controller into Python 3.9+ applications.

Purpose

Execute schema-bound lmcode DSLB v6 bytecode in pure Python with zero third-party runtime dependencies, opt-in REST dispatch, and LMCODE_RETURN framing.

When to use it

Use lmcode-python when authoring a Python CLI, service, or test harness that exposes Python objects or REST endpoints to compiled lmcode chunks.

Install

Install with python -m pip install lmcode-python (or pip install -e . from a checkout) on Python 3.9 or newer.

Commands

python3 -m unittest discover -s tests
python3 scripts/check-verifier-mutations.py
python3 -m lmcode.conformance conformance/vectors
python3 scripts/run-rest-suite.py
python3 -m lmcode.rest app.dslb host.schema.json

Inputs and outputs

  • Input: bytes DSLB v6 bytecode, bytes dsl.schema: 2 JSON, and optional LMCODE_INVOCATION_FILE manifest.
  • Output: mutated Python objects in Context, HTTP/1.1 responses on stdout via RestController, or a terminal LMCODE_RETURN frame.
  • Strings: callbacks receive UTF-8 str by default; pass raw_strings=True to receive latin1 one-codepoint-per-byte raw strings.

Safety rules

  • Set raw_strings=True on Registry.function or Registry.method when callbacks handle arbitrary binary bytes or invalid UTF-8.
  • Wrap dry-mode preview callbacks with lmcode.dry(fn) so mutating callbacks remain skipped during dry runs.
  • Keep stdout clean while RestController is serving HTTP/1.1 over sys.stdout.buffer; direct diagnostics to sys.stderr.

Worked examples

from pathlib import Path
from lmcode import Context, Registry, dry, load

registry = Registry()
registry.function(
    "double_it", ["int"], "int",
    lambda ctx, args: (args[0] * 2) & 0xFFFFFFFFFFFFFFFF,
    dry_callback=dry(lambda ctx, args: 0),
)
program = load(Path("chunk.dslb").read_bytes(), Path("host.schema.json").read_bytes(), registry)
program.run(Context(), registry)
