lmscript reference

Generated from lmscript 0.2.482: the built-in functions come from lmscript --help, the standard lmcode signatures from lmscript --lmcode-signatures, and the interfaces from the lmcode_std_v3 schema. See the user guide for the language and the skill for a compact summary.

Command line

lmscript [--check|--dry-run|--lint] [--trace FILE] [--dry-loop-limit N] [--plan-format text|json] [--resumepoint PATH] [--pref FILE] [--check-files] [--base-dir dir] [--source-name label] [--saveas FILE] <file>|http(s)://.../x.lms|-| -e <code> [args...]

Flag or formMeaning
--checkStatic check only, including compiling _lmcode_ blocks; never starts a host.
--dry-runChecks, then evaluates with effects off and prints PLAN; a reached run_lmcode starts the host once with dry metadata.
--lintStops after checking, like --check.
--trace FILEWrites an execution trace to FILE.
--dry-loop-limit NLoop iteration limit for the dry run.
--plan-format text|jsonPlan format for --dry-run.
--resumepoint PATHStart at a named resume point of a recover block.
--pref FILEProperties file.
--check-filesAlso verify path literals against the file system.
--base-dir dirBase directory for relative paths.
--source-name labelSource label used in diagnostics.
--saveas FILEDownload a remote .lms URL to FILE instead of running it; refused with exit 2 beside --check, --lint, --check-files or --dry-run.
<file> | http(s)://.../x.lms | - | -e <code> [args...]Script source: file, URL of an .lms file, standard input or inline code; the words after it are script arguments.
lmscript install github:OWNER/REPO[@TAG] | npm:@lmctl-ai/TOOL@VERSION|latestExplicit install of a native lmcode host from a GitHub release or a pinned npm package.

lmscript --lmcode-schema SCHEMA [--without-std] [--json]Print a schema summary, or the normalized schema as JSON.

Agents (agent)

SignatureDescription
agent_close(agent, [status])Closes an open agent and releases its lease; idempotent. Scope exit, recorded errors, exit and signals also close it.
agent_compact(agent, [options])Compacts an embedded conversation to its budget now (or to target_tokens), dropping the oldest exchanges and recording a compaction marker; a CLI tool manages its own context and answers status unsupported.
agent_history(agent, [options])The transcript of an open agent: the provider session reader (the lmctl tail path) for CLI tools, the native store for embedded models. Roles: user, assistant, system, tool_use, tool_result, thinking; kind compaction_summary marks a compaction marker.
agent_info(agent)State of an open agent without side effects: kind, provider, model, session_id, cwd, label, turns, pending_tools, context (managed_by host|provider, input_tokens_last, budget, compacted, estimated, compactions) and the accounting totals of its turns in this run.
agent_models(provider, [options])Model ids for one provider: the embedded provider's /models endpoint, or the known model list of a CLI tool (codex, agy, claude, kimi). Other CLI tools give ok:false with error.code unsupported.
agent_open(spec, [options])Opens a conversation with a CLI coding tool or an embedded model without a teamfile. spec: provider (required), model, kind, cwd, session_id (resume), label; embedded only: system, tools ("none" | "script" | {script:[declarations]} | {root, write, web, shell}), context {max_input_tokens, reserve_output_tokens, strategy: truncate_oldest|summarize|fail}, persist: full|none; CLI only: effort, permission: yolo|plan. A key the kind cannot honour is an author error. Returns an opaque resource handle owned by its first receiving binding, or null after writing the admission failure (busy, not found, provider down) to stderr. Dry run returns null without any effect.
agent_prompt(spec, prompt, [options])One shot: agent_open, one agent_turn, agent_close. The result carries session_id so the conversation can be resumed later with agent_open({... session_id}) or another agent_prompt. Admission failures come back as status busy or error rather than null.
agent_providers([options])The one catalog of agent providers: CLI coding tools (kind cli) and in-process embedded models (kind embedded) side by side, with transport, default model and capabilities. key_set (embedded) and binary_found (cli) are probed lazily in a real run and are null in dry run or with probe: false.
agent_tool_result(agent, results, [options])Answers a tool_request turn (tools_mode script): results is a list of {id, ok, data | error} covering exactly the pending calls; the same turn and the same turn_id finish. A wrong or missing id is error/invalid_argument and sends nothing.
agent_turn(agent, prompt, [options])Sends one user turn on an open agent and waits for the reply. The host owns the conversation: a CLI tool keeps its native session, an embedded model keeps the message list, runs granted tools and compacts the context to its budget. Exactly one accounting row (the turn_id) is written with the four token buckets and the saved price; usage and cost come back in the result. World failures are data (status != "ok"); a closed handle is error/invalid_argument.
agent_usage([options])Read-only accounting of agent turns from the same turn_usage view lmctl usage reads: this run by default (scope run), or every direct turn (scope all) narrowed by session_id, provider or since. A turn with unknown usage makes the affected total null and counts in unknown_turns.

lmcode blocks and execution

An _lmcode_ block constructs an opaque immutable program of type lmcode; it does not execute. The block ends with end _lmcode_ and runs only through an explicit run_lmcode call.

Header attributeMeaning
schema=Path of the host schema JSON file that the body is type-checked against; a schema handle from load_schema can be used in its place.
cli=Command that runs the host; binds the executable used by run_lmcode. A file-only schema requires an explicit command or a builder host.
install=Where to fetch the native host: github:OWNER/REPO@TAG or npm:@lmctl-ai/TOOL@EXACT_VERSION|latest. Check and dry run never download.
with=[...]Optional list of Data toLmcode fragments prepended to the body; may appear in either order with schema and cli.
FunctionReturnsDescriptionExample
run_lmcode(program_or_builder: lmcode, options?: map): mapmapRuns one opaque lmcode program or one sealed builder in a single host process. Single results are {ok,result}; builder results are {ok,result:[...],parts}. Args are copied; command is single-program only. Returns validated success/failure envelopes. Check never executes; dry invokes the host once with dry metadata and records its simulated envelope in PLAN.r = run_lmcode(program); require(r.ok, "host failed");
lmcode_build(host: lmcode schema | string | string list): lmcode_builderlmcode_builderCreates a run-local one-process builder for lmcode programs. host is a host-bound load_schema descriptor or an explicit command prefix string/list; add programs with one $DSLFILE fragment each, then pass the builder to run_lmcode.builder = lmcode_build(schema); builder.add(program); result = run_lmcode(builder);

run_lmcode options and result frame

ItemMeaning
options.argsString list appended to the host argv; copied, literal data, no shell, glob or environment expansion.
options.commandString or argv list, single program only: a complete command template with exactly one $DSLFILE outside argv[0].
default argvThe retained host prefix, --lmcode, a private file, then args.
builder.add(program, fragment=["--lmcode", "$DSLFILE"])Appends a program plus one argv fragment containing exactly one $DSLFILE and returns the same builder; the first run seals the builder.
single program result{ok:true, result:PAYLOAD}
builder result{ok:true, result:[...], parts:N}, even for a one-slot builder; each result is checked against the schema contract of its slot.
controlled failureReturned as data with ok false (optional validated part for builders); malformed frames, unexpected exits or mismatched envelopes are located runtime errors.
--checkNever starts hosts.
--dry-runStarts the host once with dry:true metadata and records its simulated envelope in PLAN as lmcode-host-dry.
