lmfluid reference

Complete reference for lmfluid 0.2.2: the host command line, exit codes and result frame, the context object, all six host types with their 59 method signatures, expression syntax, CSV layouts, limits, and the standard library the host ships.

Exit codes and result frame

ExitPhase in the frameMeaning
0Success
2cliCommand-line or invocation metadata error (code CLI_USAGE)
3load, runBytecode could not be read or verified (for example code LOAD_BAD_BYTECODE), or a program failed while running (for example code RUN_HOST), including the memory budget
4appApplication or output contract failure (error code APP_FAIL)

For --lmcode invocations stdout carries exactly one frame between the marker lines LMCODE_RETURN_BEGIN and LMCODE_RETURN_END. A failure frame produced by a real run:

lmfluid --lmcode missing.dslb
LMCODE_RETURN_BEGIN
{"ok":false,"phase":"load","code":"LOAD_BAD_BYTECODE","message":"cannot read missing.dslb"}
LMCODE_RETURN_END

In dry mode the same frame additionally carries dry true. run_lmcode parses the frame and returns it to the script as a map: ok and result on success; ok, phase, code, message and, for run errors, line and column on failure.

prog = _lmcode_ cli="lmfluid" install="github:lmctl-ai/lmfluid@latest";
# host program: let, arithmetic, for (k in range(a, b)) { ... }, if, method calls on fluid

r = run_lmcode(prog);
assert(r.ok);

Standard library (lmcode_std_v3)

lmfluid 0.2.2 vendors the lmcode-cpp SDK at the commit pinned in sdk.lock (93bddf1) and registers its standard library by default. The vendored schema fragment is named lmcode_std_v3 and has 206 canonical signatures: 83 function signatures and 123 method signatures on 16 standard types. They are available in every lmfluid block without a declaration, alongside the fluid context, and appear in lmfluid --lmcode-signatures.

In lmfluid programs the most useful groups are the result sink (return numbers to the outer script without a file), the float and string collections (collect values in a loop), the string functions (build expression strings and file names), and the file functions. The file functions add no sandbox: relative paths resolve against the working directory and writes overwrite.

Standard REST and CLI interfaces (current catalog, not yet in this host)

The current lmcode_std_v3 catalog in lmcode-cpp has 226 canonical signatures. The 20 signatures beyond the 206 that lmfluid vendors are the former lmcode_std_rest_v1 module: 5 functions and 15 RestExchange methods, together with 10 standard interfaces. lmfluid does not ship them yet; it picks them up when it syncs its pinned lmcode-cpp SDK and publishes a release. Until then a lmfluid program that calls rest_route or declares a RestGet handler does not compile against the lmfluid schema.
