Concept map

This page maps the main concepts of crewAI, a Python framework for agent crews and flows, to the recipes on this site. The recipes do not use crewAI; they show how each idea looks as plain lmscript.

crewAI conceptHow the recipe does itRecipe
Agent: role, goal, backstory, modelA map from agent(role, goal); the role and goal become the system promptsequential-crew
Task: description, expected output, contextA map in a list; the previous output is passed in the promptsequential-crew
Crew with the sequential processA for loop over the task listsequential-crew
Hierarchical process with a managerThe manager returns JSON naming the next worker; the script enforces the worker list and a round limithierarchical-manager
Delegation between agentsThe manager assigns a task; the script runs the named worker and reports the result backhierarchical-manager
Flow routerA validated label chooses the next agenttriage-router
Flow state and persistenceA state map written to state.json after each stepstateful-checkpoint
Checkpointing and resumeFinished steps are skipped on the next run in the same directorystateful-checkpoint
Toolstool_specs, tool_parse and tool_call: a JSON text protocol over built-in workspace tools; the script grants write and web accesstool-agent
Short-term memoryThe history option of llm_prompt, kept by the scripttool-agent
Knowledge sourcesParagraphs from local files scored by question words and passed as sourceskeyword-knowledge
Guardrails and structured outputjson_validate on a JSON reply, with the errors fed back for a retryfan-out-judge
Human inputprompt_human on a terminal, AGENTIC_APPROVE without one; the default is to rejecthuman-checkpoint
Asynchronous tasksparallel_map with a concurrency limit; results keep input orderfan-out-judge
Event listeners and usage metricstrace.jsonl with role, tokens, latency and attempts for each model callsequential-crew

Not covered yet

  • Embedding-based memory and knowledge: llm_prompt has no embeddings call, so retrieval here is keyword scoring.
  • Web search tools: the built-in webget tool fetches a known public address but does not search.
  • Token streaming: llm_prompt returns the complete reply.
  • Images and other files sent to the model: prompts are text only.
  • Planning before acting (crewAI planning): no recipe does it yet; a plan-then-execute loop fits ask_json with a step list schema.
  • Skill directories (crewAI SKILL.md packages): not mapped; the lmscript version is read_file of a skill file added to the system prompt.
  • Evaluation runs and training (crewAI test, crewai train): the offline mock checks above play the role of repeatable tests; model training itself does not apply here.
