lmbio reference

Every host type, method, flag and exit code of lmbio, taken from schema/lmbio.dsl.json, cpp/main.cpp and the README of the repository at main (version 0.1.3).

Context objects

Expression strings

Kinetic laws and rules are expression strings. They support arithmetic, powers, scientific notation and common elementary functions; the README names exp, log, sin, sqrt, min, max, sign and floor among them.

Enumerated values

The lmbio schema defines no enumerated string values. Reaction equations use the arrow form A + B -> 2 C; either side may be empty.

Limits

  • Kinetic laws are reaction extents (substance per time); a concentration species receives stoichiometry times rate divided by compartment volume. SBML hasOnlySubstanceUnits species use amounts.
  • Boundary and constant species do not change through reactions. Local kinetic parameters shadow global symbols in their reaction.
  • Assignment rules are evaluated in dependency order; cycles and unknown names are errors.
  • SBML is a subset with no conformance claim: the reader handles L3V1 and L3V2 fixed compartments, species, parameters, reactions, local parameters, arithmetic MathML and assignment and rate rules. Packages, events, delays, algebraic rules, initial assignments, function definitions, piecewise, dynamic compartments and conversion factors are rejected with a message. Units are not converted or checked.
  • There are no events. Doses and other discontinuities are modelled by restarting a run from the previous end state with set_state and append; time-dependent inputs can use min, max, sign and floor in rate expressions, but such models cannot be exported to SBML.
  • SSA: species values are molecule counts in unit-volume compartments and rate expressions are propensities. Initial counts and stoichiometric coefficients must be nonnegative integers. Hand-written propensities must include combinatorics, k*X*(X-1) for 2 X ->; mass_action writes them for you. No rules or explicit time dependence. mass_action propensities are not stored in SBML; a reloaded model uses its ODE law for SSA.
  • Sensitivities are central finite differences of two extra CVODE runs, not CVODES forward sensitivities: pick a step that dominates solver error or tighten tol.
  • Model and result objects live until the host exits; a program may use at most 4096 MiB in total by default (LMBIO_MAX_MEMORY_MB changes it) and stops with a run error, exit 3, beyond that.

CLI flags

usage: lmbio --version | --notices | --lmcode-schema [--json] | --lmcode-signatures | [--dry-run] --lmcode FILE [FILE ...]
FlagBehavior
--versionPrint the version
--noticesPrint the embedded third-party notices (SUNDIALS, pugixml, toolchain runtimes)
--lmcode-schemaPrint the schema; with --json print the embedded schema JSON. Any other extra argument is a usage error, exit 2
--lmcode-signaturesPrint the callable signatures
--lmcode FILE [FILE ...]Load every compiled .dslb program, then run them in order, stopping at the first failure
--dry-run --lmcode FILE ...Check bytecode without running the model or writing files
Environment variableMeaning
LMBIO_MAX_MEMORY_MBTotal memory budget in MiB, default 4096 on 64-bit and 256 on 32-bit; a program that needs more stops with a run error, exit 3

Exit codes

ExitMeaning
0Success, also for --version, --notices and the schema flags
2Usage error: unknown or missing flags, no file, or an invalid LMBIO_MAX_MEMORY_MB value; the usage text goes to stderr
3Bytecode load error or run error: a host validation message, a failed assertion or an exceeded memory budget

Load and run failures are reported with the phase load or run. After a successful dry run or program run the host reports ok.

Standard library (lmcode_std_v3)

lmbio at main (version 0.1.3) vendors the lmcode_std_v3 catalog with 206 canonical signatures: 83 function signatures and 123 method signatures on 16 standard types. The SDK is pinned in sdk.lock to lmcode-cpp commit 20325f7a13cbb8470af88ae3448bf0e04d40e507. The library is registered by default, needs no import and is callable in any lmbio block next to the bio context. The result sink functions are what fill the result field of the run_lmcode envelope.

Standard REST and CLI interfaces (current catalog, not yet in this host)

The current lmcode_std_v3 catalog in lmcode-cpp has 226 canonical signatures. The 20 signatures beyond the 206 that lmbio vendors are the former lmcode_std_rest_v1 module: 5 functions and 15 RestExchange methods, together with 10 standard interfaces. lmbio does not ship them yet; it picks them up when it syncs its pinned lmcode-cpp SDK and publishes a release. Until then a lmbio program that calls rest_route or declares a RestGet handler does not compile against the lmbio schema.
