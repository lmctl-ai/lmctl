lmctl skills

Provider-agnostic guides an LLM can read to use a tool. Each is a plain Markdown file — fetch the URL and follow it.

Utilities (LLM-facing)

  • lmchat — a shared file room for LLM agents (post/list/get files & one-line messages; async handoff)
  • lmsound — text → speech via AWS Polly (mp3; text or SSML; pick a voice)
  • lmprobe — structural code search
  • lmmail — simple asynchronous mail for LLM agents (mailboxes, durable messages, attachments)
  • lmfeedback — embeddable website feedback delivered to an owner's lmmail mailbox
  • communicating with mail — learn-by-doing guide: async agent-to-agent chat, remote execution, and one-shot-agent guidance over the mail lane
  • lmnote — per-user notebook files for LLM agents (push, list, read, update, delete)
  • lmsheet — simple per-user spreadsheets for LLM agents (A1 cells, rows, columns)
  • lmtext — speech → text via AWS Transcribe (audio upload, finalize, poll transcript)
  • lmfin — internal/local finance CLI: market analytics, fundamentals, macro, options/bond/DCF calculators (build from source; all --json)
  • lmbio — local computational-biology CLI: exact teaching primitives, sequence/protein/interval tools, and cache-first biomedical data pulls (all --json)

lmctl — start here

  • How to send a prompt to another agent — the one thing you give an agent so it can talk to another. Paste it into any member's session; the alias does not matter
  • Troubleshooting lmctl — busy errors, timeout units, background execution, long prompts, inspecting an agent, reseeding a drifted one, durable memory

Prompt-driven roles, not infrastructure-dictated roles. Lead, Coder and Reviewer are labels you choose in a teamfile. lmctl grants none of them any capability the others lack — you assign a role by handing over a prompt or a skill, and the pages below are those assignments. Paste one into any member and it takes on that role, whatever its alias; hand the same text to a different member and it can do the same.

Seeding deliberately tells a member almost nothing, so it cannot act before you ask it to. A member aliased Lead is the one exception: it receives the teamfile and how to invoke lmctl prompt, and is told explicitly not to use it during the seed. Every other member is told nothing at all. That is a difference in information, never in capability. (Lead is also the alias lmctl assumes when a command omits one — a convenience, not an authority.)
