lmscript commands

One canonical .lms script per lmctl command, fetched by lmctl <command> ... --save-script <file>. Scaffolding for a metalead to download, edit, and run — not a tutorial.

Available

  • plan.lms { dir, name?, pattern?+provider?+model?, members?, force? } — writes a teamfile.
  • lint.lms { teamfile } — structured error/warning summary.
  • seed.lms { teamfile } — creates real provider sessions, verified against the file.
  • prompt.lms { teamfile, alias, prompt, acceptance: [...], out? } — one dispatch, evidence-checked.

Alternatives

One script per command today. A second script for a command (a different shape of the same job) gets listed here next to the first, not silently swapped in.

Structure

Each script is VALIDATE / DISPATCH / VERIFY (or GUARDS), marked with // ==== ... ====. DISPATCH is the edit surface — replace it for the job in front of you. Don't move VALIDATE or the block after DISPATCH; that's what makes a bad form or a bad reply fail loud instead of silently.

Fetch

curl -O https://lmctl.com/lmscript/commands/plan.lms
lmctl script plan.lms request.json

--save-script does the fetch step for you once it ships; until then, curl the URL directly.

Request forms use <your-provider>, never ${Provider1}

A request form has no substitution step. ${Provider1} is for a .lmctl template quickrun expands — left in a request form, it reaches the provider registry literally and errors. Write "provider": "<your-provider>" and replace it before running.
