# lmpy publish workflow feedback

Dogfood notes for the publish-tool-book skill, based on the lmpy release and book run.

## Steps and proposed corrections

- Release prerequisites: the skill says the release tag guard is mandatory, then tells every team to stop and ask the owner to add the guard and cut the release. That conflicts with a task where the tool team is explicitly assigned the prerequisite work. Proposed wording: “If your task authorizes tool-repository changes, add a tag guard and version output before release; otherwise stop and ask the owner. Cut a new release only after all required platform CI jobs pass.”
- Version protocol: lmpy 0.1.0 printed lmpy 0.1.0 (dsl bytecode v5), which does not meet the stated exact NAME X.Y.Z check. Proposed wording: “The complete stdout of --version must be exactly NAME X.Y.Z followed by one newline; keep protocol details on --help or a separate command.”
- Autorun catalog input: the skill says to edit autorun/examples.json, but the current website generator reads scripts/autorun-examples.json. Proposed wording: “Add entries to scripts/autorun-examples.json; autorun/index.txt and autorun/index.html are generated outputs.”
- Real-session command: stable lmctl 0.2.373 returns “unknown command: autorun”; the current staging build 0.2.378 provides lmctl autorun and interprets the generated @role headers. Proposed wording: show how to install the autorun-enabled build (for example, npm install -g @lmctl-ai/lmctl@staging), then require lmctl help autorun to succeed before running the scripts.
- Scratch checker example: scripts/tools/run.sh check tools/NAME passes the directory into html.load, which reports cannot read tools/NAME. Proposed wording: run scripts/tools/run.sh check for the complete site, or use check tools/NAME/index.html for a single page; run lmhtml lint on the tool directory for its full page set.
- Scratch site inputs: the documented copy list omits lmscript-site/, whose guide is linked by the existing tools/lmscript page. A scratch check therefore reports a broken /lmscript/guide.html link even when lmpy is valid. Proposed wording: copy lmscript-site/ into the scratch root along with tools/, scripts/tools/, skills/, and homepage/index.html.
- Fresh install probe: an empty LMSCRIPT_TOOL_CACHE hit GitHub API HTTP 403 rate limiting without a token. A configured GITHUB_TOKEN allowed the same clean-cache install and verification to pass. Proposed wording: “If GitHub API rate limits the probe, retry with an authenticated GITHUB_TOKEN; do not treat a cache hit as fresh-install evidence.”
- Example generator: generated pages called every example a drawing, described local SVG/font fixtures even for lmpy, and printed the deprecated lmctl quickrun command. I changed the shared generator to use tool-neutral task wording, describe only required local assets, and use lmctl autorun. Proposed guidance: keep generated prompts and runner commands tool-neutral, and cover their actual command and labels with the generator unit test.
- Source attribution: when book.json points below examples/, the generated GitHub link incorrectly assumed examples/SLUG.lms and the existing lmpy originals live under examples/book/. Proposed fix: link to the configured file path relative to examples/ and add a nested-source test.
- Provider-run template: generated trio prompts asked the Coder to draw a PNG and called the handoff a quickrun even for non-drawing tools. Proposed fix: use tool-neutral language about completing the task, its artifacts, and verification; exercise the generated trio with actual provider sessions.
- Existing runner source: the generator prepended a second build-directory bootstrap and appended a duplicate host run to examples that already contained both. Proposed fix: detect the existing bootstrap and dsl_cli host invocation before adding defaults, and test a manual-runner example.
- Prompt line wrapping: labeling a long URL on the same line as its descriptive text exceeded the readable code-block width and clipped on desktop. Proposed fix: put link labels and URLs on separate lines and verify at desktop and mobile widths.
- Get-started commands: local paths were presented without stating that they require the lmctl repository root, and scripts were not linked. Proposed fix: provide full hosted URLs and links to each downloadable source file.
- API example correctness: the guide's expected solution for solving [1 2; 3 4] x = [5, 11] was changed from [1, 1] to [3, 1], but both are wrong: the released host verifies [1, 2]. Proposed fix: check every numeric answer by running the documented example before publishing.
- Scratch tree: a full isolated website check needs lmscript-site/ as well as the listed page trees; without it, unrelated existing links fail. Proposed fix: list every directory referenced by the complete site checker in the scratch instructions, or check the specific tool page after copying its direct dependencies.
- Page and icon review: the skill's gate list does not explicitly call for following links in the generated get-started page or adding a tool icon when a catalog entry has none. Proposed fix: check all authored internal links, verify commands from a fresh working directory, and include a per-tool icon/logo in the page review checklist.

Related generator fixes made for this run: generic task wording and autorun commands, configured-path source links, non-duplicating bootstrap/host execution, and readable prompt link formatting. The shared icon family now has an lmpy matrix icon and logo. No edits were made to the skill document.
- Provider and publish order: the skill's pre-publication real-run step uses the newly authored lmctl.com links before they exist; the provider correctly refuses them with 404s. Proposed wording: validate generated scripts locally, review and QA the pages, publish, then run solo and trio against the live references and finish with verify-live. If policy requires provider runs first, use stable source-repository URLs or a documented local preview URL in the run prompt.

## Staged-diff review corrections

- Quickstart execution: the pasted program stopped after compiling its DSL block, so it printed no answer and ran no checks. Added savedsl, host execution, failure propagation and printed JSON; verified from an empty tool cache against lmpy 0.1.1.
- Shared bootstrap compatibility: detecting an existing build-directory guard skipped all other setup, including bundled SVG inputs. Deduplicate individual setup statements so required assets and build/rendered remain available; regression coverage includes an SVG example with an existing build guard.
- Example prompt references: the matrix and least-squares pages linked the normal-quantile example while asking readers to use their own example. Generate the current example's link and test against a different book-level default.
- Numerical verification: running the guide exposed the incorrect [3, 1] assertion. Corrected it to [1, 2] and reran the documented computation.
- Authored overview logo: the decorator only injects a logo into generated fallback indexes; authored overview pages must add their own figure even though the general tools documentation says icons are picked up automatically. Proposed wording: “For an authored overview, add a figure referencing img/logo.png yourself; only generated fallback indexes add it automatically.”
- Mixed catalog icons: adding an icon to an iconed tools list exposes an un-iconed neighboring row whose bullet overlaps the icon column. Proposed fix: ensure every catalog row has an icon, or style iconless rows in a mixed list with the same reserved text inset. The shared stylesheet now reserves that space.

## GitHub README step feedback

- Architecture renderer requirement: the README step requires the architecture diagram to be rendered by the target tool, but lmpy is a headless numerical CLI and produces JSON results rather than images. Proposed wording: “For tools without a graphics renderer, render the flow diagram with lmdraw and use checked output from the target tool in the diagram; state which renderer produced it.”
- README renderer setup: the step names the artwork renderer but does not say how scripts should install or invoke lmdraw. Proposed wording: “Use the LMScript install declaration for lmdraw at the latest public release inside artwork sources, and have the render script regenerate PNGs from those checked-in sources.”
- Gallery generation for non-visual tools: the step asks for actual rendered examples but does not explain how to present tools whose outputs are numeric or tabular. Proposed wording: “For non-visual tools, draw a compact preview of values computed by the example host; run and assert the linked example sources before generating the previews.”
- README gallery layout: the prescribed two-column table suggests four examples but the minimum is three, leaving an awkward empty cell for an odd count. Proposed wording: “Use a two-column gallery, with the final example in a full-width row when the curated count is odd.”
- Mobile quick start: a published script's full URL made the three-line shell block scroll horizontally in GitHub's mobile layout. Proposed wording: “Use the published solo/trio autorun alias when available, or choose a concise install snippet so the quick-start lines fit at mobile widths; verify the block in the browser.”

Related runner issue observed during the required live solo and trio runs: each provider workflow completed and printed its report, but the autorun command then exited 1 with “No deferred tool marker found” while attempting to open a terminal with no pending marker. Proposed fix: separate successful provider completion from optional interactive terminal startup, and avoid turning a complete report into a failed command when no deferred marker exists.
