lmscript user guide

This reference follows lmscript 0.2.373, the published compiler used to check the examples. lmscript is in the @lmctl-ai/lmctl package and requires Node.js 24.15 or later.

Overview

A script is a UTF-8 .lms file. lmscript checks the whole file before running it, then normally performs a short dry preflight before the real run. The dry pass records planned writes, deletes and child processes; it is useful for review but it is not a security sandbox. Scripts run with the invoking user's local authority.

Use lmscript directly for a standalone script. Use lmctl script FILE when a script needs lmctl's installed provider configuration and agent services. lmctl autorun URL is the onboarding path for a published script with provider role declarations; it is available in the next lmctl release.

Install and first checks

npm install -g @lmctl-ai/lmctl
lmscript --version
lmscript --check examples/hello-vars.lms Ada
lmscript --dry-run examples/hello-vars.lms Ada
lmctl script examples/hello-vars.lms Ada

The static-check option checks syntax, names, calls and embedded blocks without running the script. Dry-run mode executes only the simulated pass and prints its plan. A normal run checks first, performs the preflight, then executes for real. The no-preflight option skips only the dry pass. The signature-printing option prints canonical signatures for a schema v2 native host.

Values and syntax

Values are null, booleans, numbers, strings, lists and maps. Statements end in semicolons. if, for, while and function bodies use braces. Lists and maps are mutable references; use clone when you need a shallow copy. A missing map key or list index is an error; use has or get with a default when absence is expected.

for (name in ["Ada", "Lin"]) {
  println(f"Hello, {name}");
}

fn area(width, height) {
  return width * height;
}
require(area(3, 4) == 12, "area calculation failed");

Invocation values and properties

NameMeaning
ARGVList of arguments after the script name. ARGV.get(0, fallback) safely reads the first value.
DirectoryCurrent working directory for this invocation.
NonInteractiveBoolean invocation fact used to avoid opening an interactive terminal when the run is non-interactive.
PROPSRead-only view of lmctl properties loaded from init.toml and an optional --pref file. Property keys are case-insensitive; use set_property for in-memory overrides.

Directory and NonInteractive are read-only and cannot be set in init.toml. Standalone lmscript and lmctl script can both read the configured init.toml properties; use --pref FILE before the script to overlay one explicit properties file. lmctl script also connects the lmctl automation functions to provider sessions and team services.

Data and native blocks

JSON, CSV, TOML and properties blocks parse embedded data. Command and GraphQL blocks have their own checked forms. Experimental typed native blocks compile code against a host schema. They can select a release host with an install declaration; the host provides the schema and runs saved bytecode. The schema, compiler and host must agree.

p = _dsl_ cli="lmdraw" install="github:lmctl-ai/lmdraw@latest";
scene.canvas(480, 270, "#152438");
scene.text(32.0, 76.0, 32.0, "Hello", "#f5c16c");
scene.render_png("build/rendered/hello.png", 480, 270, 1);
end _dsl_
savedsl(p, "build/hello.dslb");

lm_seed creates missing provider sessions in a teamfile. lm_prompt sends one turn to a named member. lm_terminal opens the provider's interactive interface. lm_agent and lm_agent_message address a provider directly. The remaining calls inspect or control sessions, batches, usage, teamfiles and recorded errors. Exact optional arguments are listed by lmscript help.

Command-line reference

FormUse
lmscript FILE [ARGS...]Run a standalone script; remaining words become ARGV.
lmscript --check FILE [ARGS...]Static check only; exit 0 or 2.
lmscript --dry-run FILE [ARGS...]Run the simulation and print its plan; exit 0 or 2.
lmscript --dsl-signatures SCHEMAPrint canonical DSL signatures from a schema file.
lmctl script FILE [ARGS...]Run with lmctl provider configuration and automation services.
lmctl autorun URLFetch, configure, check and run a published script that declares provider roles. Available in the next lmctl release.

Other useful options include --no-preflight, --plan-format text|json, --dry-loop-limit N, --dryrun-timeout MS, --pref FILE, --module SPEC=FILE, --trace FILE, --base-dir DIR and --source-name LABEL. Run lmscript --help for the installed compiler's full option list.

Common errors and fixes

Message patternFix
Undeclared variableAssign the name before a block if it is needed afterward; block-created names stay in that block.
Wrong argument count or unknown functionCheck spelling and arity with lmscript help NAME or lmscript help.
Missing map key or list indexUse has(key) or get(key, default) before reading optional data.
Check error in a native blockCompare the call and types with the host's schema summary; use its JSON schema output for compiler input and match the pinned host release.
require failed or run-time errorRead the located diagnostic, correct the input or condition, then rerun --check before the script.
Provider unavailableRun lmctl init, choose an installed provider and model, then rerun the team workflow.

Exit codes

  • 0: success, including successful check or dry run.
  • 1: run-time failure, failed require/assert, or usage error.
  • 2: static/check failure or failed explicit dry run.
  • Other values may be requested by exit(code); signals use 130 or 143.

Limits and trust

lmscript is not a sandbox. File, process and network functions use the invoking user's authority. Dry run is an effect preview and does not make untrusted code safe. Read scripts before running them, especially scripts that seed or prompt providers, write files, or launch processes.

lmscript collections are native lists and maps. In _dsl_ bytecode, collections are host-defined objects with methods such as len and at; the bytecode has no general list or map value type.
