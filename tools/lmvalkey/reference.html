lmvalkey reference

Complete command-line flag reference, integrated HTTP REST endpoints, host schema types and methods, standard lmcode_std_v3 REST and CLI interfaces, and exit codes for lmvalkey v0.1.0.

Server and host CLI flags

Flag or environment variableArguments / defaultDescription
--version / -vnonePrint the lmvalkey server version string (lmvalkey v=0.1.0) and exit 0.
--port<port> (default 6379)TCP port for native Valkey/Redis RESP connections (also auto-detects incoming HTTP REST requests).
--rest-port<port>Dedicated TCP port for the integrated zero-auth HTTP JSON REST server (for example, 8080).
--bind<addr> (default 127.0.0.1)Bind RESP and REST listeners to the specified network interface addresses.
--daemonizeyes | no (default no)Run the lmvalkey server as a background daemon process.
--requirepass<password>Require AUTH password on native RESP connections (HTTP REST endpoints remain unauthenticated).
--lmcode<file.dslb>Load and execute a compiled LMScript bytecode file against the embedded lmvalkey schema.
--lmcode-schema[--json]Print the exact embedded lmvalkey schema JSON bytes to stdout and exit 0.
--lmcode-signaturesnonePrint all 245 canonical context, function, and method signatures (19 host + 226 standard library).
VALKEY_HOST / REDIS_HOST127.0.0.1Target host IPv4 address used by _lmcode_ ValkeyClient connections before falling back to in-memory mode.
VALKEY_PORT / REDIS_PORT6379Target TCP port used by _lmcode_ ValkeyClient connections.

Integrated HTTP REST endpoints

HTTP methodPath patternRequest bodyResponse envelope
GET/none{"ok":true,"result":...} server health and status summary.
GET/pingnone{"ok":true,"result":"PONG"}.
GET/get/<key>none{"ok":true,"result":"<value>"} (or null if key does not exist).
POST/set/<key>raw value bytes{"ok":true,"result":"OK"} after storing the request body under <key>.
POST/set/<key>/<val>none{"ok":true,"result":"OK"} after storing <val> under <key>.
GET/keysnone{"ok":true,"result":["k1","k2",...]} listing all keys (KEYS *).
GET/keys/<pattern>none{"ok":true,"result":[...]} listing keys matching the glob pattern (such as user:*).
PUT/keys/<key>raw value bytes{"ok":true,"result":"OK"} RESTful key upsert from request body.
DELETE/keys/<key>none{"ok":true,"result":1} (number of deleted keys).
POST/cmd["CMD","arg1",...] or {"command":"CMD","args":[...]}{"ok":true,"result":...} executing any Valkey command against the unified datastore.

Exit codes

Exit codePhase / modeMeaning
0SuccessServer exited cleanly, or _lmcode_ bytecode / schema / signature command completed and all assertions passed.
2CLI usage (phase "cli")Missing --lmcode <file> argument or invalid host CLI invocation (code CLI_USAGE).
3Load / run error (phase "load" or "run")Bytecode file missing or corrupt, schema hash mismatch, RESP command error reply, or failed runtime assertion.
