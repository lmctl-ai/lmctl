tree-sitter-lmcode guide

This guide explains the tree-sitter-lmcode grammar architecture, external scanner state serialization, $return and R49 entry syntax nodes, and the 127-body conformance gates.

Overview

tree-sitter-lmcode combines a declarative grammar.js with a stateful C external scanner in src/scanner.c. Because generated src/parser.c, src/grammar.json, and src/node-types.json are committed in the repository, C, Rust, Go, and editor consumers can compile parser.c and scanner.c directly without Node.js.

Grammar and external scanner rules

The grammar models every construct in the standalone lmcode language: typed fn declarations, @NAME and @"PATH" annotations, implements Interface clauses (R47-R49), typed let bindings, compound assignments, if/else, while, range and foreach loops, switch arms, break/continue, method chains, enum member access, map entries using =>, qw/qi/qf word and number lists, %json literals, and ${...} outer-language splices. Assignment-only $return, $return.name, and $return[expr] targets produce return_assignment nodes while rejecting $return in read positions, declarations, nested paths, or compound writes.

REST, CLI, and rule entry syntax coverage

Path-annotated standard REST and CLI entries—such as @"/users/:id" fn get_user(x: RestExchange) -> void implements RestGet or @"status" fn status(x: RestExchange) -> void implements CliCommand—parse into function_declaration nodes carrying an annotation child (with the string or identifier annotation) and an implements_clause child naming the standard interface (RestGet..RestOptions, RestHandler, CliCommand, CliOption). Calls to rest_config, rest_route, rest_serve, rest_stop, and rest_cli parse as call_expression nodes.

python3 scripts/controls.py

Conformance and mutation controls

Five Python verification gates enforce grammar quality: scripts/conformance.py parses all 127 pinned real-world lmcode bodies without ERROR or MISSING nodes; scripts/negative.py verifies 21 syntax-refusal cases; scripts/incremental.py tests serialized scanner state across single-byte and multi-line edits; scripts/scanner-limits.py stress-tests deep heredoc queues and splice nesting; and scripts/controls.py mutates the scanner and grammar to confirm the test suite catches regressions.
