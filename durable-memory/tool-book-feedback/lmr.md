# lmr tool-book dogfood feedback — 2026-10-21

Review findings from publishing the lmr example book, including native-host release checks, text results, shared quickrun generation, and site validation. The proposals below record changes needed in the publishing workflow and its guidance.

## Findings

- Release prerequisite step: the lmr 0.4.0 binary supports the required schema and install protocol, but lmr --version prints extra parenthetical build details. The skill says the output must be exactly NAME X.Y.Z, while there is no diagnostic for a version command that contains a valid prefix plus extra text. Proposal: keep the exact-output requirement and explicitly call out that the tool's version command must contain no suffix; the tag workflow should compare the built output to the tag on every platform before publishing.
- Example book generation: the generator required every example preview to be a PNG, even though the skill allows a printed result and lmr is a statistics tool. Setting a text output path in book.json failed at PNG parsing. Proposal: document PNG previews for visual tools and UTF-8 text result paths for tools whose useful output is textual; generate a preformatted sample page and link the captured result.
- Generated quickrun source: examples that saved and ran their own bytecode received a second generated system ${dsl_cli(...)} --dsl ${out} wrapper, which failed when the example did not define out or ran the host twice. Proposal: state whether source examples should include their own runner, and have the generator append one only when no runner is present.
- Generated example copy: pages called every task a drawing and described bundled SVG/font handling even for non-visual tools. The command still used the deprecated lmctl quickrun alias. Proposal: use neutral terms such as example/result and the current lmctl autorun command; mention bundled inputs generically.
- Trio template: the shared quickrun template told the Coder to complete a drawing task and report a rendered PNG, and told the Reviewer to judge the drawing. That makes non-visual tool quickruns incorrect even when book.json is accurate. Proposal: make the shared handoff and review prompts use neutral task/result/output language, while the per-tool task supplies the domain-specific work.
- Scratch site checklist: the documented copy set omitted lmscript-site/, but the copied tools/lmscript pages link to /lmscript/guide.html. The scratch tools check failed that internal link until the built lmscript-site directory was copied to scratch/site/lmscript. Proposal: add cp -a lmscript-site "$scratch/site/lmscript" to the scratch setup commands.
- Scratch checker command: the documented run.sh check tools/NAME passed the directory as one HTML fixture and failed trying to load it as a file. I updated run.sh so a directory argument maps to the full tools catalog check. Proposal: explain that directory-form check runs the catalog suite, or expose a genuinely scoped directory check before documenting it.
- Mobile visual gate: generated example prompts and the get-started commands put long URLs in preformatted code, which required horizontal scrolling on desktop/mobile. Updating the shared code-block wrapping rule removed the clipping without changing copyable text. Proposal: add a browser-based overflow check to the visual QA step for long URLs in code blocks and keep generated text wrapping in the shared style.
- Curated catalog step: the skill names autorun/examples.json, but this checkout uses scripts/autorun-examples.json and the catalog builder reads that exact file. Proposal: correct the filename and say entries require both a unique name and an absolute script URL.
- Release guidance: this task explicitly included fixing the release prerequisite and cutting a guarded release after CI, while the skill's safety rule says never to change a tool repository or cut a release during a website documentation task. Proposal: distinguish website-only tasks from tasks whose explicit scope includes tool-source/release work, and say that the latter may proceed only with owner authorization and green platform CI.
- Real provider runs: the pre-publish solo autorun used the actual provider but its book URLs returned 404 because the skill schedules provider runs before the site push. Proposal: run content and script checks before publishing, then run provider sessions after deployment so they can use the live book; keep verify-live as the final gate after those runs.
- README artwork for a non-visual tool: the README section asks for a hero and a diagram, but does not say how to make tool-specific artwork when the released host returns statistics rather than images. I used lmr to compute a seeded Welch comparison, quantile, fit and optimizer result, then used lmdraw to visualize those returned values. Proposal: explicitly recommend using the target tool for its real result data and lmdraw for the rendered chart or diagram.
- README renderer preflight: running the documented static check before the first artwork execution failed because lmscript check does not fetch an install-at-latest host from an empty tool cache. Proposal: execute the renderer once with an isolated cache to install the public releases, then run source checks using that populated cache; state this ordering in the README step.
- README artwork release resolution: repeated install-at-latest renderer invocations hit the unauthenticated GitHub API rate limit even though the release binaries were already cached. An authenticated GitHub token resolved the request, and the render script now reuses the isolated release binaries after its first run. Proposal: recommend one renderer process or cache reuse and mention that GitHub API authentication may be needed when the rate limit is reached.

## Evidence

- lmr repository: https://github.com/lmctl-ai/lmr; starting release v0.4.0 and published release v0.4.1.
- The released binary's --dsl-schema --json is available and matches native/schema/lmr.dsl.json; --dsl-signatures is supported. The v0.4.0 release contains Linux, macOS, and Windows assets plus SHA-256 metadata.
- Fresh-cache install-enabled examples for a normal quantile, exact line fit, and BFGS minimum passed and printed deterministic expected values. Generator text-output support is covered by focused unit tests.
