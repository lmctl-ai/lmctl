lmcode-cpp

lmcode-cpp (formerly the C++ DSL SDK) is the experimental C++17, standard-library-only runtime for lmscript _lmcode_ bytecode: loader, verifier, VM and host registry in one header, include/dslvm.hpp. This quick reference is kept at the former address; the same tool is documented at /tools/lmcode-cpp/.

Install and build

npm install -g @lmctl-ai/lmctl
git clone https://github.com/lmctl-ai/lmcode-cpp
g++ -std=c++17 -Ilmcode-cpp/include host.cpp -o host

The SDK is header-only. Hosts vendor include/dslvm.hpp with all stdlib/*.hpp files by pinned hash. The published compiler requires Node.js 24.15.0 or later.

Host protocol and schema

ItemMeaning
BytecodeVersion 6 only (DSLB v6); older and newer versions are refused.
SchemaA dsl.schema 2 JSON document with name, types, functions, context and interfaces. Program::load takes its exact bytes for the SHA-256 binding; the SDK never reads its content.
host --lmcode-schema --jsonHost protocol flag: print the exact schema JSON the compiler uses.
host --lmcode-signaturesHost protocol flag: print Registry::signatures(), diffed against lmscript --lmcode-signatures schema.json.
host --lmcode FILE.dslbHost protocol flag: load and run a compiled program file.
Exit codes2 for compilation or argument errors, 3 for bytecode load or run errors, 4 for application failures.
ResultOne standard JSON result line, for example {"ok": true, "result": ...}, which run_lmcode returns as ok and result.

SDK API

SDK nameRole
dslvm::RegistryDeclares context types, functions and methods with exact argument and return type strings and stores the C++ callbacks. Default construction includes lmcode_std_v3.
Registry(StdMode::Disabled)Registry without the standard catalog.
dslvm::register_std(registry)Idempotently registers the complete standard catalog.
registry.context(name, type)Declares a schema context variable and its host type.
registry.method(type, name, params, returns, callback)Binds a host method; the callback receives void* self and dslvm::Args.
registry.function(name, params, returns, callback)Binds a host function; the callback receives dslvm::Args.
registry.signatures()All registered signatures including std.
registry.host_signatures()Registered signatures excluding std.
registry.matches_schema_signatures(...)Accepts host-only or already merged declarations and rejects host drift.
registry.std_collections()Arena for standard collection values returned by native callbacks (make_* helpers); cleared at entry and exit of each Program::run.
dslvm::Program::load(bytecode, schema, registry)Verifies format, schema binding and imports, then returns a runnable program.
program.run(context, registry)Runs the chunk with live host objects.
dslvm::Context, context.set(name, pointer)Maps schema context variable names to host-owned object pointers.
dslvm::ValueINT (int64), FLOAT (binary64), STR, BOOL, VOID or OBJ (host pointer plus schema type name); Value::none() and Value::string(...) construct values.
dslvm::ErrorThrown by load and run; catch it around both.
dslvm::read_file(path)Reads a file as bytes without text conversion.
dslvm::report_ok(json), dslvm::json_escape(text)Emit the standard JSON result line.

Standard catalog

Every default dslvm::Registry includes the lmcode_std_v3 standard catalog: 226 canonical signatures (88 functions and 138 methods on 17 standard types), pinned in std.lock as version 3 of std/lmcode-std.schema.json. Registry(StdMode::Disabled) opts out and dslvm::register_std(registry) enables it idempotently.

The catalog includes the standard REST and CLI surface: the 10 interfaces RestGet, RestPost, RestPut, RestDelete, RestPatch, RestHead, RestOptions, RestHandler, CliCommand and CliOption (each takes one RestExchange and returns void), the functions rest_config, rest_route, rest_serve, rest_stop and rest_cli, and 15 RestExchange methods.

SignatureMeaning
rest_config(string, string) -> voidSets a named REST configuration value.
rest_route(string, string, string) -> voidRegisters a route; route templates accept {param} and {rest...} as well as :param and :rest... placeholders.
rest_serve() -> voidStarts serving the registered routes.
rest_stop() -> voidStops the server.
rest_cli(StrList) -> stringStateless CLI mode: dispatches options, commands and REST routes from an argument list without resetting outer run state.

Minimal example

A host author compiles a block against the schema file of the host under development and saves bytecode for the host to load:

p = _lmcode_ schema="schema.json";
g.say("Hello from lmcode");
end _lmcode_
savedsl(p, "demo.dslb");
lmscript demo.lms demo.dslb
./host --lmcode demo.dslb

Users of a released host X name it on the block and run it directly; run_lmcode returns ok and result:

prog = _lmcode_ cli="X" install="github:lmctl-ai/X@latest";
...
end _lmcode_
r = run_lmcode(prog);
