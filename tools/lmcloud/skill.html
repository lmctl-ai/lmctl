lmcloud authoring skill

lmcloud provides the shared procedural lmcode schema (schema/lmcloud.dsl.json) and Go hostkit (github.com/lmctl-ai/lmcloud/hostkit) implemented in lockstep by lmaws, lmazure, lmgcp, and lmoci.

Purpose

Use lmcloud to write provider-neutral LMScript cloud programs that run identically against the in-memory reference fake adapter, local cloud emulators (awssim, azuresim, gcpsim, ocisim), and provider hosts (lmaws, lmazure, lmgcp cloud, lmoci) without rewriting application logic.

When to use it

Choose the shared lmcloud schema when a workflow uses portable object storage, queues, key-value tables, IAM policy linting and attachment, serverless functions, user directories, cost caps, or operational metrics across AWS, Azure, GCP, and OCI. Choose a provider-specific schema only when inspecting vendor-specific resources outside the shared contract.

Install

Declare any lmcloud-compatible provider host in an LMScript program or load schema/lmcloud.dsl.json directly when running conformance suites against hostkit.

p = _lmcode_ cli="lmaws" install="github:lmctl-ai/lmaws@latest";
# Or bind lmazure, lmoci, or lmgcp cloud against the shared schema:
s = load_schema(schema="schema/lmcloud.dsl.json");

Commands

Every host built on hostkit/cloudhost accepts the same top-level CLI flags, with an optional leading cloud subcommand word for hosts that also serve a legacy vendor-specific schema.

lmaws [cloud] --version
lmaws [cloud] --help
lmaws [cloud] --notices
lmaws [cloud] --lmcode-schema --json
lmaws [cloud] --lmcode-signatures
lmaws [cloud] --lmcode-signatures --without-std

bash scripts/test-hostkit.sh

Inputs and outputs

Programs interact with the cloud context (type Cloud) inside an _lmcode_ block. Operations return typed handles including ObjectMeta, ObjectSummary, ObjectListPage, QueueMessage, QueueMessageList, TableItem, TablePage, Policy, LintReport, LintFinding, FunctionConfig, FunctionInvokeResult, User, UserPage, Session, CostReport, CostLineItem, MetricsReport, OpMetrics, and CloudError. When cloud.set_abort_on_error(false) is set, failed calls record status in cloud.last_error() instead of halting the VM.

Safety rules

By default, hosts with no endpoint and no live opt-in run against an in-process fake adapter and make zero network calls. Plain HTTP endpoints are permitted only for loopback addresses (127.0.0.1, localhost, ::1) targeting local emulators: 127.0.0.1:4566 for awssim, 127.0.0.1:4577 for azuresim, 127.0.0.1:4588 for gcpsim, and 127.0.0.1:4599 for ocisim. Live mode requires explicit double opt-in environment gates, immutable live-policy.json validation, an append-only fsynced recovery journal with flock leases and OwnerNonce tags, and reservation-based cost caps via cloud.set_cost_cap_usd(cap) (monotone-decreasing, default $0.05, maximum $0.25).

Worked examples

Example 1: Portable object storage, queue processing, and cost reporting across providers.

p = _lmcode_ cli="lmoci" install="github:lmctl-ai/lmoci@latest";
  cloud.set_cost_cap_usd(0.05);
  cloud.bucket_create("artifacts-bkt");
  let meta = cloud.object_put("artifacts-bkt", "build/info.txt", "v1.0.0");
  assert(meta.exists() && meta.size() == 6, "object upload failed");

  cloud.queue_create("events-q");
  let msg_id = cloud.queue_send("events-q", cloud.object_get("artifacts-bkt", "build/info.txt"));
  let batch = cloud.queue_receive("events-q", 1, 30, 0);
  assert(batch.len() == 1, "expected 1 message");
  cloud.queue_ack("events-q", batch.at(0).receipt());

  let rep = cloud.cost_report();
  print(rep.summary());
end _lmcode_
r = run_lmcode(p);
assert(r.ok, "run failed");

Example 2: Combining key-value tables with standard lmcode_std_v3 REST and CLI interfaces.

p = _lmcode_ cli="lmazure" install="github:lmctl-ai/lmazure@latest";
  @"/items/:table/:pk"
  fn handle_get(x: RestExchange) -> void implements RestGet {
    let item = cloud.item_get(x.param("table"), x.param("pk"));
    if (!item.exists()) {
      x.status(404);
      x.json("{\"error\":\"not_found\"}");
      return;
    }
    x.json("{\"pk\":\"" + item.pk() + "\",\"role\":\"" + item.get_string("role") + "\"}");
  }

  @"seed"
  fn cmd_seed(x: RestExchange) -> void implements CliCommand {
    cloud.table_create("users-tbl");
    let row = cloud.item_new("u-100").set_string("role", x.body());
    cloud.item_put("users-tbl", row);
    x.send("seeded");
  }

  rest_config("prefix", "/api");
  let seed_res = rest_cli(str_split("seed -- admin", " "));
  let get_res = rest_cli(str_split("/api/items/users-tbl/u-100", " "));
  print(seed_res + " -> " + get_res);
end _lmcode_
r = run_lmcode(p);
assert(r.ok, "table REST/CLI example failed");

Errors and exit codes

In-band cloud errors map to the ErrorCode enum: OK, INVALID_ARGUMENT, NOT_FOUND, CONFLICT, PRECONDITION_FAILED, UNAUTHENTICATED, PERMISSION_DENIED, COST_CAP_EXCEEDED, and INTERNAL. Inspect cloud.last_error().code(), http_status(), provider_code(), and message() when abort_on_error is false. Process exit code 0 indicates success; exit code 2 indicates CLI usage or invalid environment configuration (CLI_USAGE); exit code 3 indicates host runtime, assertion, memory budget, or unhandled cloud error failure (APP_FAIL / RUN_HOST); exit code 4 indicates bytecode loading or schema contract failure.
