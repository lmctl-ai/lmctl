integration reference

Reference tables for the setup GitHub Action, e2e.yml workflow inputs, T0/T1 scenarios, mono-test inventory classifications, negative control scripts, and exit codes.

Action actions/setup inputs and outputs

Name Direction Values and description
lmctl input latest | staging | X.Y.Z | none — version of @lmctl-ai/lmctl to install in a private RUNNER_TEMP prefix.
tools input Comma-separated NAME[@TAG][+EXTRA_ASSET...] list (such as lmmock@v0.1.36+examples.tar.gz,lmgit@latest).
miniplayer input Full 40-hex commit SHA of lmctl-ai/miniplayer to build from source, or empty string.
lmctl-version output Exact resolved semantic version of @lmctl-ai/lmctl installed by the action.
bin-dir output Directory holding the installed host binaries.
INTEGRATION_ASSETS_<NAME> env export Directory containing SHA-256-verified extra release assets for tool <NAME>.

Scenario matrix

Tier Scenario path Execution chain Assertions
T0 scenarios/t0-claudemock lmscript lm_prompt -> in-process ClaudeMock Verifies ok, scripted error, empty-reply rejection, and delayed reply without network calls.
T0 scenarios/t0-fanout lmscript lm_fanout -> 3 ClaudeMock members Verifies deterministic slot ordering, per-slot error capture, and ok-but-empty detection.
T0 scenarios/t0-provider-smoke-mock lmscript -> ClaudeMock Verifies fresh seed, ping, three-turn conversation state, and provider failure handling.
T1 scenarios/t1-lmmock-ai lmscript -> lmctl -> miniplayer acp -> HTTP -> lmmock llm-api.lms Verifies non-empty reply and audits lmmock to confirm model mock-agent was requested.
T1 scenarios/t1-lmmock-modes lmmock exec per mode -> miniplayer acp -> lmctl Verifies ok, retry (429 then 200), unauthorized (401), rate-limit, server-error (500), and bad-json error_class plus GET /__requests counts.

Negative control suites and mono-test classifications

Script or classification Target Verification contract
tests/setup-selftest.sh actions/setup scripts Fails as expected on corrupted SHA256SUMS, corrupted extra asset, missing entry, unknown tag, or branch name pin.
tests/scenario-controls.sh T0 and T1 scenarios Fails as expected on wrong reply, empty reply, unscrubbed LMCTL_SELF_SESSIONID, unreachable URL, or wrong request count.
tests/suite-controls.sh suites/mono-test/run.mjs Verifies uncovered failure is red, unexpired allowlist is ALLOWED, expired allowlist is red, and code mutations fail.
run.mjs --control broken-bin all ported mono-test suites Replaces lmctl with an exit-0 no-op binary; any suite staying green is flagged VACUOUS and fails the gate.
inventory.tsv classes 88 mono-test entries Classified into ported (executed), support (shared library), skip-host (requires mono checkout), and skip-live (requires live vendor credentials).

Exit codes

Code Meaning
0 All scenario assertions, mono-test suites, and negative control checks passed.
1 Scenario failure, checksum mismatch, vacuous suite detection, or expired allowlist entry.
2 Usage error: scripts/run-scenario.sh given a directory without run.sh, scripts/hermetic.sh called without a command, or suites/mono-test/run.mjs given an unknown --control value, unknown suite id, or malformed allowlist entry, or unable to find lmctl.
