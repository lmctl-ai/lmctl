lmcode-js skill

Use lmcode-js to embed the DSLB v6 bytecode verifier, 226-signature standard catalog, and REST/CLI controller into Node.js 22+ and 24+ applications.

Purpose

Run schema-bound lmcode DSLB v6 bytecode in pure JavaScript with lossless 64-bit BigInt math, raw byte buffers, REST/CLI dispatch, and LMCODE_RETURN framing.

When to use it

Use lmcode-js when building a Node.js host tool, CLI, or test runner that executes compiled .dslb v6 programs without native addons.

Install

Import @lmctl-ai/lmcode-js and @lmctl-ai/lmcode-js/rest in Node.js 22 or 24 LTS with zero external npm runtime dependencies.

Commands

npm run verify:pins
npm test
npm run mutation
npm run conformance
npm run conformance:rest
npm run sample-suite

Inputs and outputs

  • Input: Buffer or Uint8Array DSLB v6 bytecode, exact schema JSON bytes, and optional LMCODE_INVOCATION_FILE manifest.
  • Output: mutated JS host objects in Context, HTTP/1.1 traffic on stdout via RestController, or a terminal LMCODE_RETURN frame.
  • Types: integers default to BigInt (or safe Number with { ints: 'number' }); strings default to UTF-8 (or Buffer with { rawStrings: true }).

Safety rules

  • Enable { rawStrings: true } on callbacks that must preserve invalid UTF-8 bytes or interior NUL bytes as Node Buffer instances.
  • Keep default BigInt mode for callbacks that handle full signed 64-bit integer ranges outside Number.MAX_SAFE_INTEGER.
  • Pass { dry: previewCallback } options only for side-effect-free preview callbacks during dry invocations.

Worked examples

import { Context, Program, createRegistry } from '@lmctl-ai/lmcode-js';

const registry = createRegistry();
registry.context('greeter', 'Greeter');
registry.method('method Greeter.say(string) -> void', (greeter, text) => {
  greeter.messages.push(text);
});
const program = Program.load(bytecode, schemaBytes, registry);
const context = new Context({ greeter: { messages: [] } });
program.run(context);
