lmcode-cpp reference

Reference tables for the lmcode-cpp SDK: the C++ host API in include/dslvm.hpp, the command-line conventions a host built on it follows, exit codes, the lmcode_std_v3 standard catalog (226 canonical signatures, std.lock version 3) and the standard REST and CLI interfaces. Facts come from the repository README, std/lmcode-std.schema.json, the stdlib schema fragments and stdlib/rest.hpp.

C++ host API

NameRole
dslvm::RegistryHolds the host's context declarations, functions and methods, declared with the schema's type strings. A default Registry also installs the standard catalog.
Registry(dslvm::StdMode::Disabled)Creates a registry without the standard catalog; group binders such as dslvm::stdlib::register_string can then be applied manually.
Registry::context(name, type)Declares a schema context variable and its host type.
Registry::method(type, name, params, returns, callback)Binds a method; the callback receives void* self and dslvm::Args&. Overloads with distinct parameter tuples are allowed; the same tuple twice is refused.
Registry::function(name, params, returns, callback)Binds a host function; the callback receives dslvm::Args&.
Registry::signatures()Returns the sorted canonical signature strings, including the built-in standard, for comparison with lmscript --lmcode-signatures.
Registry::set_std_output(stream)Redirects standard-library output, for example to std::cerr while a REST program owns stdout.
dslvm::Program::load(bytecode, schema, registry)Verifies bytecode version 6 against the exact schema bytes and the registry; refuses the file before anything runs.
Program::run(context, registry)Executes the body of the chunk.
Program::entries()Rule entries in source order; each Program::Entry has name, annotation, iface, returns and params.
Program::call(i, context, registry, args)Runs rule entry i with the given arguments; returns Value::none() for a void interface.
dslvm::ContextLive host objects for one run: set(name, pointer); set_dry(true) selects dry execution.
dslvm::ValueINT (int64), FLOAT (binary64), STR, BOOL and OBJ (host pointer plus schema type name); constructors include Value::integer, Value::string, Value::boolean and Value::none.
dslvm::ErrorThrown by load and run, and by host code to report a run-time failure.
dslvm::dry(callback)Marks a callback for the optional dry slot of a registration.
dslvm::read_file(path)Reads a bytecode or schema file as bytes.
dslvm::VERSIONThe bytecode format version the SDK reads, currently 6; every other version is refused.

Host CLI flags

lmcode-cpp is a header, not a program. Hosts built on it follow the same host protocol, which lmscript drives when a block names the host with cli= and is executed with run_lmcode.

FlagEffect
HOST --lmcode-schema --jsonPrints the host schema JSON the compiler binds to.
HOST --lmcode-signaturesPrints Registry::signatures(), one sorted canonical signature per line.
HOST --lmcode FILE.dslbLoads and runs a compiled program file.
lmscript --lmcode-signatures schema.jsonCompiler side of the parity check; diff its output against the host's.

REST and CLI interfaces

The former lmcode_std_rest_v1 module is part of lmcode_std_v3. It serves HTTP/1.1 requests read from an input stream and written to an output stream; there is no network listener. Handlers are annotated rule entries that implement one of ten standard interfaces, each with the shape (RestExchange) -> void, and they run strictly one at a time.

InterfaceSignatureUse
RestGetRestGet(RestExchange) -> voidHandler for GET requests.
RestPostRestPost(RestExchange) -> voidHandler for POST requests.
RestPutRestPut(RestExchange) -> voidHandler for PUT requests.
RestDeleteRestDelete(RestExchange) -> voidHandler for DELETE requests.
RestPatchRestPatch(RestExchange) -> voidHandler for PATCH requests.
RestHeadRestHead(RestExchange) -> voidHandler for HEAD requests.
RestOptionsRestOptions(RestExchange) -> voidHandler for OPTIONS requests.
RestHandlerRestHandler(RestExchange) -> voidGeneral handler bound to a route with rest_route.
CliCommandCliCommand(RestExchange) -> voidCommand dispatched by rest_cli.
CliOptionCliOption(RestExchange) -> voidOption handler dispatched by rest_cli.

Functions

SignatureMeaning
rest_config(string, string) -> voidStores a configuration key and value. The keys prefix and base_path set the route prefix; max_body_bytes sets the request body limit when given a positive decimal number. Refused once rest_serve has been called.
rest_route(string, string, string) -> voidRegisters a route. Path templates accept {param} and {rest...} as well as :param and :rest... placeholders. Routes are frozen once rest_serve has been called.
rest_serve() -> voidMarks the program as serving: after the body finishes, the host serves the input stream until end of input, rest_stop or a framing error. A second call is an error.
rest_stop() -> voidStops serving.
rest_cli(StrList) -> stringStateless CLI mode: dispatches an argument list to options, commands and REST routes without resetting the outer run state. The method defaults to GET; --method or -X sets it, --body or -d sets the body, positional words form the path, and words after -- are joined with spaces as the body.
