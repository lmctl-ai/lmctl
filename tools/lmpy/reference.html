lmpy reference

Complete reference for the lmpy numerical host as released in lmpy 0.1.46: command-line flags, exit codes, the result frame, every host type, method and function, the out context object, the expression grammar, and the standard lmcode catalog it ships. The host tables are generated from the output of lmpy --api-md, which the repository keeps as native/API.md.

See also the quick reference, the skill and the guide.

Command-line flags

CommandResult
lmpy --lmcode FILE [FILE ...]Runs the bytecode files in order. Every input is loaded before any part executes. Prints exactly one result frame; several files return a result array in registration order.
lmpy --dry-run --lmcode FILE [FILE ...]Validates and loads the inputs without running callbacks and returns null results. A dry flag that contradicts real-mode invocation metadata is refused as a usage error.
lmpy --lmcode-schemaPrints the plain-text API summary: the context line, then functions and types with their signatures.
lmpy --lmcode-schema --jsonPrints the exact schema bytes the bytecode binds to (the same bytes as native/schema/lmpy.dsl.json and the release asset lmpy.dsl.json).
lmpy --schema [--json]Older alias of --lmcode-schema still accepted by the 0.1.46 command line.
lmpy --lmcode-signaturesPrints the canonical signatures of the whole registry, one per line: 757 lines in 0.1.46 (551 host lines including the context line, plus 206 standard catalog signatures).
lmpy --api-mdPrints the generated API reference as Markdown.
lmpy --versionPrints the release identity in the form lmpy X.Y.Z.
lmpy --help, lmpy -hPrints the usage text and exits 0.

Exit codes

CodeMeaningFrame phase
0Success.none (ok is true)
2Usage error: missing or invalid arguments, invalid invocation metadata. LMScript compile errors in the calling program also exit 2, from lmscript.cli
3Load or run-time error: unreadable or mismatched bytecode, or a failing host call such as a singular matrix.load or run
4Application failure: out.fail was called or at least one out.check, out.close or out.close_rel failed.app

Result frame

The host writes one frame to standard output: a line LMCODE_RETURN_BEGIN, one JSON document, and a line LMCODE_RETURN_END. run_lmcode decodes it and returns the JSON document as an LMScript map.

okalwaystrue on success, false on any failure.

result.checks.passed, result.checks.failed, result.checks.failuresdefault resultCounts of passed and failed checks and the list of failures, each with name and detail.
phaseok is falsecli, load, run or app.
codeok is falseAn error code such as CLI_USAGE, LOAD_BAD_BYTECODE, LOAD_SCHEMA_MISMATCH, LOAD_UNBOUND, RUN_HOST, RUN_ERROR or APP_FAIL.
messageok is falseThe diagnostic. Run-time messages start with dsl line N:C and name the operation.

Statistics

Probability distributions (pycli stats_dist, stats_dist_to), special functions (special_fn, special_fn_to), numpy-compatible random numbers and classical tests. Distributions follow scipy.stats 1.16 parameter names and formulas (each family is a port of its scipy class; special functions are scipy's own xsf/Cephes code or Boost.Math with scipy's policies). dist(name, opts) takes the scipy parameters plus loc (and scale for continuous families); pycli's names are accepted too: uniform low/high, gamma shape, lognorm mu/sigma (of the underlying normal), poisson lam. Families: norm, t, uniform, expon, gamma, beta, lognorm, chi2, genextreme, genpareto, skewnorm, johnsonsu, levy_stable (S1), nct, ncf, vonmises, truncnorm, weibull_min, cauchy, laplace, logistic, gumbel_r, pareto, rayleigh, f, poisson, binom, zipf, betabinom, nbinom, geom. Probabilities outside [0, 1] are errors; NaN inputs give NaN. Discrete ppf(0) and isf(1) are the first support point (pycli). Random variates reproduce numpy.random.Generator(PCG64(seed)) exactly for the numpy-sampled families (pycli's rvs; nct, skewnorm, betabinom and levy_stable use PCG64(seed) and its jumped() stream as pycli did); the quantile-sampled families (genextreme, genpareto, johnsonsu, truncnorm, weibull_min, cauchy, gumbel_r, pareto) use numpy's uniform stream through lmpy's quantile function. Deviations from scipy: Student t cdf/ppf use Boost (scipy: CDFLIB), Bessel/Airy outside [-10, 10] use Boost (scipy: AMOS), levy_stable integrates with Gauss-Kronrod (scipy: QUADPACK), Poisson ppf uses the generic discrete search.

Optimisation, roots, quadrature and linear programming

Minimisation (minimize, scipy.optimize.minimize), nonlinear least squares (least_squares, scipy.optimize.least_squares with curve_fit covariances), bracketed and multivariate roots (root_scalar, root), adaptive quadrature (quad, QUADPACK) and LP/MILP (linprog, HiGHS). Objectives, models and equations are expression strings in pycli's grammar; the unknowns are named by a StrVec, and option keys starting with $ bind constants and data vectors (opts().set("$x", xs)). Numerical outcomes are a status (OK, NO_CONVERGENCE, EVAL_LIMIT, TIME_LIMIT, NON_FINITE, NUMERICAL_FAILURE, ...); bad input is a run-time error. Every expression evaluation counts against max_evals (default 500000) and the optional time_limit (seconds); a stopped run reports the best point so far.

Ordinary differential equations

Initial value problems dy/dt = f(t, y) with expression right-hand sides (pycli ode_solve, ode_solve_to; scipy.integrate.solve_ivp). rhs[i] is the expression for d(state[i])/dt in the state names, t, y[i] and $-bound constants (opts().set("$beta", 0.3)). Methods RK45 (default), RK23, DOP853, Radau, BDF are ports of scipy's solvers (same step control, dense output and finite-difference Jacobian); LSODA is an automatic switch from RK45 to BDF when Hairer's stiffness test fires, not ODEPACK. Options (pycli names and defaults): method, rtol (1e-6), atol (1e-9, float or one per state), t_eval (ordered times; t0/t1 are added when missing) or max_output_points (101 uniform samples), max_step, first_step, events (StrVec of expressions whose zeros are located by brentq on the dense output), direction (Vec of -1/0/1), terminal (Vec: 0 = record only, k = stop at the k-th occurrence), max_events (32: a non-terminal event stops the run with EVENT_LIMIT at that count), max_evals (200000 expression evaluations), max_steps (10000 accepted steps). Result statuses: OK, STEP_SIZE_TOO_SMALL, NO_CONVERGENCE, EVAL_LIMIT, STEP_LIMIT, EVENT_LIMIT, NON_FINITE (a NaN/inf RHS or event value stops the run); a non-OK run keeps the samples computed so far and ends at the last accepted state.

Interpolation

1-D interpolants and n-D radial basis functions (pycli interp_eval, interp_eval_to; scipy.interpolate). interp(kind, x, y[, opts]) builds an Interp once; evaluate, differentiate and integrate it as often as needed. Kinds: linear (make_interp_spline k=1), nearest (interp1d nearest), cubic (CubicSpline, option bc_type not-a-knot (default) / natural / clamped / periodic), pchip (monotone Fritsch-Carlson, PchipInterpolator), akima, makima (Akima1DInterpolator), smoothing (make_smoothing_spline; lam >= 0, omitted = generalised cross-validation; lam / h^3 is capped at 1e11 as in pycli), rbf (RBFInterpolator; kernel thin_plate_spline (default), linear, cubic, quintic, multiquadric, inverse_multiquadric, inverse_quadratic, gaussian; epsilon (1), smoothing (0), degree). x must be finite and strictly increasing (rbf: one row per node). Option extrapolate: error (default: a point outside the nodes is a run-time error), nan, or extend (the end polynomial; rbf: the nodes' bounding box is the range). At a node a piecewise interpolant takes its right-hand piece. An rbf whose system is singular or that misses its own nodes by more than 1e-6 of the data scale has status SINGULAR / ILL_CONDITIONED and cannot be evaluated.

The 20 additional signatures are the former lmcode_std_rest_v1 module: five functions and 15 RestExchange methods, together with 10 standard interfaces. lmpy 0.1.46 does not ship them: its vendored catalog is the 206-signature one above, and lmpy --lmcode-signatures lists no rest_ function and no RestExchange method. lmpy picks them up when it syncs the lmcode-cpp runtime and publishes a release. They are listed here so a program can be planned against the catalog; do not call them in a block that targets lmpy 0.1.46.
