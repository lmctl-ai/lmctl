lmdraw script authoring skill

Use lmdraw to create editable 2D scenes and render still images or animation frames through typed lmscript calls.

Purpose

Write lmscript programs that create retained vector nodes, import supported SVG artwork, update node attributes and render PNG images or frame sequences.

When to use it

Choose lmdraw for diagrams, title cards, vector overlays and scripted 2D animation. Use it when the same scene should produce many frames by changing a few attributes. Use a 3D host when the work depends on solid geometry, perspective or physical lighting.

Install

Download the latest lmdraw binary from GitHub Releases. Install Node.js 24.15 or newer and use the published lmscript compiler with npx. Source builds require C++17, CMake, Ninja and Python 3; the project README has the build steps.

Commands

npx --yes --package=@lmctl-ai/lmctl -- lmscript scene.lms build/scene.dslb
lmdraw --dsl build/scene.dslb
lmdraw --schema
lmdraw --schema --json
lmdraw --dsl-signatures

Compile against the exact JSON printed by lmdraw --schema --json. The short --schema summary is for people; the JSON is the compiler input.

Inputs and outputs

  • Programs use an _dsl_ block and schema version 2. The host reads bytecode version 5.
  • scene.canvas(width, height, background) starts a scene. Its coordinates are CSS pixels, with x increasing right and y increasing down.
  • Nodes are returned as handles. node.set_attr(name, value) uses SVG-style attribute names such as fill, stroke, opacity, transform, font-size and text-anchor.
  • scene.load_svg(path, id) reads a supported SVG from assets/ and returns the node with that id. Repeated loads of the same file can obtain additional handles.
  • PNG outputs are written below build/rendered/. Loops can write numbered frames, which ffmpeg can encode as video.

Safety rules

  • Run only bytecode you trust. The VM has no instruction or allocation budget.
  • Canvas dimensions, image pixel totals, scene nodes, SVG input and bytecode have host-side limits. Keep rendering scale within the total-pixel limit.
  • SVG files must be direct children of assets/. External files, URLs, scripts, stylesheets, CSS classes, event handlers, DTDs, animation and filters are refused.
  • PNG paths must be direct children of build/rendered/. Path traversal and symbolic-link escapes are rejected.
  • There are no DSL list values. Host collections, where provided, use len(), at(i) and foreach; lmdraw itself does not expose a collection API.
  • Use float(i) when a loop index participates in float arithmetic. Integer and float values do not mix implicitly.

Worked examples

A five-minute path is: compile a title card, run it, inspect the PNG, load an SVG node, then change an attribute and render again.

  1. Make a title card with scene.canvas, scene.rect and scene.text. Set typography and decoration using node.set_attr.
  2. Load an SVG by path and element id, then change a presentation attribute such as opacity or fill before rendering.
  3. For animation, loop over frame indices, compute t as float(i) / float(frame_count - 1), update string-valued attributes with str(lerp(...)), and call scene.render_png for each numbered frame.
  4. Encode frames with ffmpeg using a fixed frame rate and pixel format. Keep the numbered PNGs when you need to inspect or regenerate the video.
  5. Use scene.measure_text before positioning a label. Text uses bundled Noto Sans; complex-script shaping and bidirectional layout are not provided.

Errors and exit codes

Exit code 0 means success. Exit code 2 indicates invalid command-line arguments. Exit code 3 indicates bytecode loading, verification or a DSL host-call error. Exit code 4 indicates another application failure. A rejected SVG usually needs unsupported CSS, filters, scripts or external references removed. An output path error means the PNG must be written directly inside build/rendered/.

How to verify

  1. Compile using the schema bytes from lmdraw --schema --json.
  2. Compare lmscript --dsl-signatures schema.json with lmdraw --dsl-signatures when checking schema and registry parity.
  3. Run the bytecode and confirm the host prints its success result.
  4. Check image dimensions and inspect the render visually. Re-run the same input and compare PNG bytes when determinism matters.
  5. For animation, count the numbered frames, inspect first, middle and last images, and verify the encoded video dimensions and frame rate.
