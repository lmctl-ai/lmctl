lmcode-cpp-sample skill

Use lmcode-cpp-sample as a verified blueprint for embedding lmcode-cpp (include/dslvm.hpp) in a C++17 host application with schema discovery, R49 rule entries, dry mode, and LMCODE_RETURN framing.

Purpose

Demonstrate a complete, byte-pinned C++17 host application that exposes a 45-signature Shop/Ledger domain to DSLB v6 bytecode and passes the shared sample suite.

When to use it

Use lmcode-cpp-sample when learning how to bind C++17 domain objects, overloaded methods, operators, R49 rule entries, and LMCODE_RETURN result envelopes with lmcode-cpp (include/dslvm.hpp).

Install

Clone lmctl-ai/lmcode-cpp-sample and run ./test.sh with C++17, Python 3, Node 24, and a DSLB v6 capable lmscript compiler (set LMSCRIPT_BIN to select one).

Commands

git clone https://github.com/lmctl-ai/lmcode-cpp-sample.git
cd lmcode-cpp-sample
python3 scripts/sync.py check
./test.sh
./build/lmcode-cpp-sample --version
./build/lmcode-cpp-sample --lmcode-schema --json
./build/lmcode-cpp-sample --lmcode-signatures
./build/lmcode-cpp-sample --lmcode sample-suite/bytecode/001-literals.dslb

Inputs and outputs

  • Input: compiled .dslb v6 bytecode files from sample-suite/bytecode/, embedded sample.dsl.json schema, and optional LMCODE_INVOCATION_FILE manifest.
  • Output: print trace lines, entry NAME = VALUE lines, tagged host_summary JSON diagnostic, and terminal LMCODE_RETURN_BEGIN / END frame.
  • Locks: sdk.lock and suite.lock pinning every vendored SDK and corpus byte by commit SHA and SHA-256.

Safety rules

  • Verify sdk.lock and suite.lock before building so vendored SDK and corpus files never drift silently.
  • Preserve raw byte strings across Ledger.note and JSON diagnostics without lossy UTF-8 replacement.
  • Check LMCODE_INVOCATION_FILE dry mode before seeding or mutating external state so dry runs remain side-effect-free.
