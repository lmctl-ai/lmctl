A second look: CPU Cycles

Contents

Raster is the fast preview path. The same scene can use CPU Cycles for final lighting, reflections and roughness. A Cycles-enabled lmvideo binary and matching module must be installed locally; this candidate is not a published installable release.

Save each displayed source at its named examples/book/ path before running its compile/render commands. The output below is the structured result from the locked chapter capture; timing fields describe that historical run and vary on another machine.

lmscript examples/book/cycles-still.lms

Source

mkdir("build");
program = _lmcode_ cli="lmvideo";
video.size(960, 540); video.fps(24); video.frames(48);
video.output("build/turntable.mp4"); video.begin();
let scene = scene3d().background("#09111f");
scene.camera(camera3d().look_at(4.5, 2.5, 5.5, 0.0, 0.0, 0.0)
  .perspective(45.0, 0.1, 100.0));
scene.directional_light(2.0, 3.0, 4.0, "#ffffff", 2.0);
let body = scene.add(mesh_box(1.4, 1.0, 0.6),
                     material("#e76f51", 0.25, 0.45));
for (frame in range(0, video.count())) {
  video.frame();
  body.rotation(0.0, 360.0 * video.t(), 0.0);
  scene.time(video.time());
  let image = scene.render_image(
    video.width(), video.height(), "cycles", 16, 4, 42, true);
  canvas.clear("#09111f");
  canvas.image(image, 0.0, 0.0);
}
video.end();
end _lmcode_
savedsl(program, "build/turntable.dslb");

Raw LMScript source (candidate must be published first)

The seven render_image arguments are width, height, renderer name, samples, maximum bounces, repeatable seed and denoise. A build without Cycles must report an error rather than silently render with raster. Video generation compiles once and renders each frame; these captures are local verification evidence, not a new website benchmark run.

Source and releases: github.com/lmctl-ai/lmvideo.
