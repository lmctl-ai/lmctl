## Findings

- The skill says to add catalog entries in autorun/examples.json, but this checkout has no such file; the input is scripts/autorun-examples.json. Proposal: correct the path in the skill and its worked example.
- The documented scratch copy omits lmscript-site/, so a full tools check reports broken links from /lmscript/index.html to /lmscript/guide.html. Copy lmscript-site contents into the scratch site's lmscript/ directory before checking. Proposal: include those copy commands in the dry-run recipe.
- The sample command scripts/tools/run.sh check tools/NAME treats tools/NAME as one HTML fixture and fails to read it. Proposal: use scripts/tools/run.sh check with no argument for the full tools tree, or pass one real HTML file to the narrower fixture mode.
- The quickrun generator appended an execution of a variable named out even when a selected source saved bytecode to a string literal. This made the existing loop-row example fail to render in the book. The generator now derives out from savedsl() when it is absent and has a focused regression test. Proposal: document the output variable convention or keep the inference and its regression test.
- book.json can point to get_started.html, but no generator creates that page; the linked page must be authored manually and start with an Overview-like h2 to pass the guide checker. Proposal: explicitly call out this manual page step in the skill.
- The skill says to use a pinned lmhtml host, while scripts/tools/run.sh resolves lmhtml@latest through an install declaration. GitHub API rate limiting blocked the default host resolution with HTTP 403; setting LMHTML to the cached released executable allowed checks to pass. Proposal: align the skill with the runner's actual pin/resolution behavior and explain the LMHTML override for rate-limited runs.
- Rendering the 720 × 540 plate-with-holes example at supersample 6 exceeded the generator's 180-second render timeout and had no checked-in preview fallback. The two smaller selected examples rendered successfully. Proposal: state the render timeout in the skill and keep selected book examples compact, or check in a verified preview for expensive examples.
- The real trio run passed its volume and bounds checks, but the STL review found four non-manifold edges where the separate raised rim touches the plate. File existence, volume and bounds did not establish a watertight export. Proposal: for STL tasks, say: "Check triangle count, edge multiplicity and mesh volume after export; report any non-manifold edges and do not call the mesh print-ready unless it is watertight."
- The public lmcad guide uses lmcad --schema and lmcad --schema --json, but the released v0.1.3 binary accepts --dsl-schema and --dsl-schema --json. The book skill should treat the release protocol as authoritative and send this mismatch to the tool owner. Proposal: update the guide and signature example to the released command names before the next book release.
- The repository has no examples/README.md or checked-in render previews. The explicit examples list and rendered output path in tools/lmcad/book.json let the generator build still-life.html anyway. Proposal: lmcad should add a short examples manifest and expected-output checks to test.sh; keep explicit book metadata as the fallback for repositories with no generated example catalog.
- The lmcad example URL in book.json returns 404 until the book is published. The pre-publication provider run can use the local generated page/source, but the prompt includes an unavailable public URL. Proposal: dogfood with the local generated example path and verify that the URL resolves after deployment; do not treat a pre-publish 404 as a release failure.
- The source examples declare a local schema path, while generated book scripts rewrite that declaration to cli plus install. The rewrite was needed to render in a clean scratch directory. Proposal: keep this transformation explicit in the book skill and validate the exact generated source before using it as evidence.
- The scratch command initially omitted homepage/index.html, so the checker reported broken links to /. Copying homepage/index.html to the scratch root made the full tools check pass. The skill now says to do this.
- The skills checker rejected the valid autorun example because the checked-in lmctl subcommand list omitted commands with optional arguments; the refresh script expected two spaces after the command name and skipped autorun [example] and hello [name]. Proposal: parse the optional argument token and validate the refreshed vocabulary against the current command-list section. This has been fixed and the skills check passes.

## README-step dogfood — 2026-10-22

- The README recipe asks for gallery captions linking to each published examples-book page, but it does not say to add gallery examples to tools/lmcad/book.json when they are not selected already. Two otherwise valid example links would have pointed to missing pages. Proposal: require checking each source slug against generated tools/NAME/examples/ pages and adding missing gallery items to book.json before the README push.
- The README render instructions do not account for examples whose savedsl() target is hard-coded. Invoking the compiler with a README-specific output filename silently left no such bytecode; the renderer then tried to run the wrong file. Proposal: make the render workflow discover and run the bytecode target declared by the example (or standardize examples on an out variable).
- Compiling a committed lmscript file with install="github:lmctl-ai/lmdraw@latest" triggered a GitHub API lookup and failed with HTTP 403 even though the exact v0.2.0 host was already cached. --no-preflight did not bypass this install lookup. The README render script now compiles a temporary copy against schema bytes from the cached host and runs that exact host. Proposal: document a supported offline cached-host workflow, or make install resolution use a valid cached release when the API is rate limited.
- Related tool/generator improvement: add an offline/resolve-from-cache switch to lmscript tool installation and a helper that compiles a source against the cached host schema without changing the committed install declaration. This would remove the temporary-source rewrite from docs/readme/render.sh.
