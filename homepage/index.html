From AI orchestration to AI automation

People set the goal.
AI teams do the work.

lmctl grows from a clear view of agent sessions into repeatable, provider-flexible workflows. Keep the important decisions with people; automate the steps in between.

Read the docs →

Level 1

Manage agent sessions

Give provider sessions a team and member name in a plain-text .lmctl teamfile, so work is organized by role instead of an opaque session ID. Use lmctl status, lmctl running, lmctl tail, lmctl usage and lmctl ratelimit to inspect activity, history, recorded costs and provider limits.

Learn more about named sessions

Level 2

Coordinate a team with a person in the loop

Compose a Lead, coding and review members across supported provider CLIs in a readable teamfile; members can communicate through the Lead and call across teams. lmctl plan, lmctl lint, lmctl seed adds missing session IDs, and lmctl prompt sends a request through the team without copying messages between provider tools.

Learn more about team orchestration

Level 3

Delegate the middle of the workflow

Set the requirement and acceptance criteria up front, then let a Lead assign work and coordinate its members while you step away from each turn. lmctl can track prompts and runs, but the workflow and approval boundaries come from your instructions; review the result yourself before accepting it.

Learn more about hands-off delegation

Level 4

Automate repeatable AI work

After a person sets the request and acceptance rules, an agent can help draft an LMScript automation. Run it with lmctl script: a workflow can read a request form, call team members or provider sessions, check acceptance conditions and route independent review. People still define the rules and judge the result; scripts have full local authority, so run only code you trust.

Learn more about AI automation

Keep your choices open

  • Provider: mix tools such as Claude Code, Codex, Copilot CLI, Qwen Code, Antigravity and OpenCode in one team.
  • Workflow: keep team roles and repeatable steps in files you can read, review and change.
  • Context: keep project knowledge in durable memory so it can outlast a provider session.
