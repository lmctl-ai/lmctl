lmaudio reference

Every type, method, flag and exit code of lmaudio 0.2.2, generated from the schema and signature list that the released binary prints, with notes from the repository README and examples.

Command line

usage: lmaudio --version | --notices | --lmcode-schema [--json] | --lmcode-signatures | [--dry-run] --lmcode FILE [FILE ...]
Command or variableEffect
lmaudio --versionPrints the release identity, for example lmaudio 0.2.2.
lmaudio --noticesPrints the third-party software notices with the upstream license texts.
lmaudio --lmcode-schemaPrints the embedded schema as readable JSON.
lmaudio --lmcode-schema --jsonPrints the exact schema bytes the compiler binds a program to (schema version 2, name lmaudio).
lmaudio --lmcode-signaturesPrints every canonical signature the host registry provides, one per line, standard catalog included.
lmaudio --lmcode FILE [FILE ...]Runs compiled lmcode program files. This is what run_lmcode calls; the compiler owns the program files.
lmaudio --dry-run --lmcode FILERuns a program without writing any file. The flag comes before --lmcode. The result envelope carries dry true.
LMAUDIO_MAX_MEMORY_MBEnvironment variable: total memory budget in MiB, default 4096. A value that is not a positive whole number is a usage error on every command.

Standard library (lmcode_std_v3)

The lmcode runtime inside lmaudio registers the standard catalog itself, so every block can call it next to the host API. lmaudio 0.2.2 reports 377 canonical signatures from lmaudio --lmcode-signatures: 171 host signatures and 206 standard ones. The current lmcode_std_v3 catalog has 226 canonical signatures; the 20 that this release does not ship are the REST and CLI group described at the end of this section. The lmaudio implementation source is private, so the public repository carries no std.lock; the count above is what the released binary reports. lmaudio picks up the remaining 20 signatures when a release built on the newer runtime ships; confirm with lmaudio --lmcode-signatures.

Strings are raw bytes: lengths and offsets are byte based. Standard collections and Json values live for one run. Relative file paths resolve against the working directory of the host process, and the standard file functions apply no sandbox or root check. In lmaudio the lmcode_return functions are the way to send values back to LMScript.

REST endpoints and stateless CLI interfaces

The current lmcode_std_v3 catalog includes the former lmcode_std_rest_v1 module: 10 standard interfaces, 5 functions and 15 RestExchange methods. They are documented here so that a program written for another host reads the same way, but lmaudio 0.2.2 does not provide them: a block that calls one of them compiles with a current lmscript and is then refused by the host at load time with code LOAD_UNBOUND, before any host work starts.
