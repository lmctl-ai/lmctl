Teamfile format

If you just ran lmctl plan (or lmctl quickrun), you have a new <name>.lmctl file and a comment inside it pointed you here. This page covers the whole loop: generate → edit → lint → seed.

Generate: what lmctl plan gave you

lmctl plan writes a starting point, not a finished team. It is a real, loadable teamfile, valid the moment it is generated, but built from the pattern or flags requested rather than the actual project. Add members, remove them, swap providers, or rename aliases.

Edit: what is in the file

A teamfile is plain text: no YAML, no JSON, and no special editor. Every line starting with _MEMBER_ declares one team member. Everything else is free-form text for headers, blank lines, and reminders. It is a space-separated list of key=value pairs. Wrap a value in double quotes if it contains spaces, such as model="claude opus 5"; otherwise quotes are not needed.

The _MEMBER_ line

A member line looks like this:

_MEMBER_ alias=Coder provider=claude model="claude-opus-5"

Valid provider= values include claude, codex, gemini, copilot, opencode, qwen, agy, kimi, dsh, hermes, pi, and lmplayer. For an alternative team lead, see Cross-team calls.

FieldRequired?What it means
aliasyesThe name you call this member; it must be unique.
provideryesWhich AI provider CLI runs this member.
modelnoA specific model, or the provider default when omitted.
effortnoA reasoning-effort or tier variant where supported.
sessionidnoFilled automatically by lmctl seed.
sessiondirnoRuns this member from another directory.
teamfilenoPoints to another team lead instead of an AI provider.

Adding, removing, or reassigning members

Copy an existing member line, give it a new alias, and choose a provider. Do not set sessionid; lmctl seed creates it. To remove a member, delete its line. To rename or reassign one, edit alias or provider; if the provider changes, delete the old sessionid first.

# Backend team
# Lead plans and delegates. Coder implements. Reviewer checks the Coder's work before anything ships.
_MEMBER_ alias=Lead provider=claude
_MEMBER_ alias=Coder provider=codex model="gpt-5.6-luna"
_MEMBER_ alias=Reviewer provider=claude

Lint: check before seeding

lmctl lint ./team.lmctl

lint checks syntax and, where possible, provider and model names. Warnings are advisory and still exit zero; errors mean the file is malformed and exit one. Fix what the error names and run lint again.

notice: checking teamfile and models ...
warning: [Lead] model "not-a-real-model-xyz" is unknown to the lmprice catalog for provider "claude" (214 known) -- not necessarily wrong: may be a model too new for lmprice to have published yet, or a typo. A matching lmprice catalog/alias entry would resolve this; lint cannot otherwise confirm whether claude accepts it.
notice: 0 errors, 1 warning
ok
notice: checking teamfile and models ...
error: Lead: Invalid provider "cladue"
notice: 1 error, 0 warnings

Seed: create provider sessions

lmctl seed ./team.lmctl

Seeding starts a real provider session for each member missing a sessionid, then writes the resulting session id and resolved directory back into the file. Existing sessions are left alone. If no model was specified, seed records the provider's observed model when it can determine one; it never overwrites a model= you already set, and if the provider's choice cannot be determined, it leaves model= unset and warns instead of guessing.

Seeding is a real provider call and can take a few seconds per member; a “still launching” line every 5 seconds is normal, not a hang. A member with an existing sessionid is not touched.

To replace one member without disturbing the rest, delete only that member's sessionid and seed again.

After seeding

lmctl prompt ./team.lmctl Lead "hello"
